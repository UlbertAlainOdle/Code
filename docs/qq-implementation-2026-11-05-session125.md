# 第125轮：戳一戳后普通聊天反复生成失败

## 原因及证据

用户提供主人私聊的完整顺序：一次普通阅读交流成功，随后戳一戳；下一句个人感受已形成话题卡，但主答失败；之后执行全部停止成功，继续普通提问仍失败。核对到5条实际失败入站，均为generation_failed，约0.5～1.9秒结束。第一次确有个人话题committed；后来8条个人事件停止已提交并保持suppressed。

根因在 `QQSocial.prompt_state`：存在最近戳一戳情绪时，需要判断共享聊天的情绪是否更新。服务端实际绑定的 `previous_web_time` 返回日期字符串，情绪表的at是浮点Unix时间；原代码直接用大于号比较，抛出str与float不可比较的TypeError。异常发生在主回答调用前。普通回复成功前该戳一戳记录仍保留，因此后续新消息再次触发同一异常；停止事件没有删除独立情绪状态，无法解除此条件。

数据库副本、原共享档案时间适配器、实际请求模型和QQ响应器的隔离重放，在修复前6条输入全部复现同一TypeError且未到达模拟生成器；修复后同6条全部正常到达。5条使用实际失败消息的投递摘要，另1条为普通输入。8项实际关联/修前后对照检查通过。这不是截获的完整供应商提示，也不是代理真实QQ收发。

两个用户提示来自同一外围失败处理：已有话题提交时提示不要重复提交；没有新的提交时使用通用生成失败提示。原错误路径只保存通用generation_failed，没有记录本地异常位置，导致后端难以直接看出根因。没有证据表明这是后台无限重发；实际记录对应多条新输入反复撞到同一条件。

- `saya_app/services/qq_social.py`：按现有聊天时间合同使用parse_time归一化，再比较Unix时间。兼容无时区/带时区/UTC字符串、数字和datetime；缺失或无效时间不作错误比较，原情绪锁优先级保持。
- `saya_app/services/qq_bridge.py`：失败日志增加异常类型、代码文件/行号和既有错误码，不记录异常正文、对话、账号、URL、请求头或凭据，不转发原异常给QQ。
