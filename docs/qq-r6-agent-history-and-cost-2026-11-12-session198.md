## 已实现与上线

默认 Agent 的 `memory.query` 和 `memory.read` 沿用第197轮有限历史证明。原问题由主机绑定，模型工具参数不能切换过去／现在；当前权限、来源、历史屏障、正文指纹、删除及生命周期检查不放宽。返回旧版本时，候选摘要也使用同一旧正文，避免夹入当前理由。审计记录历史修订和当前修订，不恢复快照或回灌旧库。

新增 `memory_agent_recall.py`。对于直接命名对象、询问已记录理由的问句，主机先经原 Agent Loop 执行查询；摘要截断时，经同一 Loop 读取匹配原编号的正文，然后才调用模型。工具权限、步数、次数、成本、延迟及取消限制继续生效；主机读取不冒称模型决策，也不计为模型 API 请求。建议、引语和明确要求一般原理或推测的问句不套用该主机流程。查询摘要仍为240字符，单条全文仍受原4000字符公开结果上限限制，截断标记保留。

召回规则要求直接使用已有理由，不主动扩写未问的因素或索取额外背景，也不能据一个理由排除其他动机。原220-token边界块上限保持。Agent的全文证据审计使用实际可见正文，界面摘要继续限长。

成本复核发现原 Agent API 请求没有进入既有用量账本。现按每次实际 provider 请求记录成功／失败、可用token及耗时，接入原网页／QQ回答分项；无用量保留未知，账本失败不重发模型请求。只有计数器进入账本，不传递提示词、凭据或推理内容。主机本地读工具不产生API计数，查询／全文读取仍计入原工具预算。

## 真实 QQ 增量

沿用已获准的主人与原机器人私聊，实际12条入站、12条文字回执，每条从OneBot重新读取，并核对入站身份、原文、发送账本和实际回执。包括虚构长期记忆保存、原编号和版本读取、CAS安排变更、两条普通自然问句、清理与原结果查询，以及一个用量探针。没有使用 `/recall` 代替默认Agent验收。

两条自然历史／当前问答均由默认Agent完成，各2步、1次工具调用，只有同一原编号入选。过去回答引用第1版原始理由，当前回答使用第2版安排及理由，未混用两个时期。用户授权清理后，首次确认被拒绝，没有删除；保留该失败回执，重新预览同一编号及正文后确认成功。首次拒绝发生在受管重启之后，原因未单独定位，不能把它写成跨重启确认通过。原保存操作重查准确区分原已提交和当前已删除。

测试记忆从当前JSON及原生条目中消失，墓碑存在；原有30条原生记忆、110条版本、36条证据及192条原墓碑与实机前备份逐行一致。原保存账本及保存时版本保持。两条自然问句生成的一张仅含问题的临时话题卡保留在存储中；删除后其纪元不匹配，实际详情查询返回当前不可见。没有把它当成仍可用卡片，也没有发送未通过读取核对的停止命令。

另在QQ界面触发一次实际戳一戳。界面观察到通知及机器人回戳，桥接账本为 `processed`、戳一戳状态为 `poke`。没有文字答复，因此只签通知与回戳链路，不能代签显式停止事件后由模型生成文字的用例。

用量修复后，真实QQ探针和戳一戳合计记录4次后台模型请求、14058 token：回答一次，话题路由一次，选择器两次，用量未知数为0。修复前两条Agent自然问答的token没有账本依据，保留缺口，不回填。全轮可核对token下界为206408，并非包含未知用量的完整总成本。
