# QQ 主人身份与群接入完善

日期：2026-10-24。分支：`codex/qq-message-bridge`。

## 主人身份修复

原实现把“可以共享个人记忆”误当作“知道这是主人”的唯一提示条件。现在每轮 QQ 请求都会根据服务器配置的 `OWNER_IDS` 独立验证发送人 QQ 号，并向模型传入当前 QQ 号与主人身份。昵称、引用消息和用户自称不能获得主人身份。

即使共享记忆关闭，主人仍会被识别为主人。群内也能识别主人，但群内不开放个人记忆或私聊管理权限。既有历史中错误的身份判断会被当前可信身份提示纠正，不删除聊天历史。

新增 `/whoami`（别名 `/owner`、`/身份`）确定性查询当前身份；`/status` 同时显示身份和记忆模式。主人私聊中的内置命令不受普通聊天冷却限制，但仍受消息去重和队列容量限制。

## 入群与群回复

- `SAYA_QQ_AUTO_ACCEPT_OWNER_INVITES=true`：只自动同意已配置主人通过 QQ 发出的机器人入群邀请，成功后持久化开启该群的 @回复。库默认值为 false，本机部署已为用户开启。
- 非主人发出的邀请保留为待审核，不自动加入。主人可以在 QQ 好友私聊或受管理 Token 保护的网页管理区同意/拒绝。
- QQ 可能直接完成入群，不产生审核请求。收到机器人自身入群通知、且通知操作者是主人时，也会开启该群回复。
- `SAYA_QQ_OWNER_GROUP_AUTO_ENABLE=true` 提供兼容路径：主人在新群首次明确 @机器人发送文字，会为该群开启回复；库默认关闭，本机已开启。仅结构化 @或真实 CQ @有效，文本段里伪造 CQ 码、过期消息、非主人消息均不能授权。手动关闭的群不会被这条路径重新打开。
- 同意入群与开启群回复是两步状态：只有 OneBot 成功确认同意后才记录群授权。网络超时/重启导致结果不明确时，不自动重复同意，也不擅自开启该群回复。
- 群内所有成员在授权群中 @机器人即可聊天，同群按发言人隔离上下文。主人在群里也不能读取个人长期记忆。
- 群回复开关是持久化配置。关闭后保留群成员身份；关闭状态优先于环境变量静态白名单，也阻止主人新邀请自动绕过关闭状态。主人显式再次开启或手动审核同意可重新授权。

采用 [OneBot 请求事件](https://github.com/botuniverse/onebot-11/blob/master/event/request.md) 与 `set_group_add_request` 协议，并核对 [NapCat 4.18.41 实现](https://github.com/NapNeko/NapCatQQ/blob/v4.18.41/packages/napcat-onebot/action/group/SetGroupAddRequest.ts)。主人邀请认证来自已验证事件的 `user_id`，不依据群名称或聊天内容。

## QQ 私聊管理命令

| 命令 | 作用 |
| --- | --- |
| `/whoami` | 查看当前 QQ 与主人身份；普通用户也可查询自己的身份 |
| `/groups` | 查看已加入/已授权群与回复开关 |
| `/requests` | 查看待审核邀请编号、群号与邀请人 |
| `/approve 邀请编号` | 同意入群并开启 @回复 |
| `/reject 邀请编号` | 拒绝邀请 |
| `/group allow 群号` | 开启指定群回复；机器人尚未加入时仍需通过 QQ 邀请加入 |
| `/group block 群号` | 关闭指定群回复，不退群 |

除身份查询外，表中管理操作仅允许已配置主人在好友私聊中执行。普通用户发同样的命令会被拒绝，不会交给模型模拟执行。

## 网页管理

在 `/static/qq.html` 输入管理 Token、检查连接后，页面会展示已配置主人 QQ、主人邀请策略、群列表、回复开关和待审核邀请。可以直接启停群回复、同意或拒绝邀请。Token 只保留在当前页内存，刷新或点击“锁定”即清除。

新增管理接口均要求 `SAYA_QQ_ADMIN_TOKEN`：

- `GET /api/qq/management`
- `PUT /api/qq/groups/{group_id}`，正文 `{"enabled": true}`
- `POST /api/qq/invites/{request_id}`，正文 `{"approve": true}`

公开状态只返回是否配置主人、群授权数量与待审核数量，不公开主人 QQ、邀请 flag 或 Token。

## 数据与限制

新增群授权和邀请表，位于原 `knowledge_base/qq/bridge.sqlite3`，兼容原消息与历史表。部署前已在 `.runtime/napcat/backup-before-owner-groups` 备份本机 QQ 数据和环境配置。

- 待审核邀请最多 128 条，24 小时后过期。只保存处理需要的群号、邀请人、flag 和状态，不保存邀请说明正文。处理完毕或结果不明确时清除 flag。
- 重复事件、同时审核和重启恢复不会自动重复执行同意/拒绝。无法保证 QQ 平台上的绝对一次执行，结果不明需在 QQ 核对。
- 只处理“邀请机器人入群”，不自动批准其他人加入群，不提供踢人、禁言、转让群等管理能力。
- QQ 平台的邀请权限、群主审核、人数限制与账号风控仍生效，不能通过代码绕过。
- 机器人在升级前已被人工加进的群可通过 `/groups` 查看，再用 `/group allow 群号` 启用。升级前收到而未上报保存的旧邀请需在 QQ 中处理或重新发出。
- 本期不新增通用群共享知识库；群内仍按成员分别保留近期上下文。

## 验证

新增主人身份与群接入测试涵盖：共享记忆关闭时识别主人、群内主人无个人记忆权限、冒充主人无效、主人邀请自动同意、非主人邀请待审核、批准后群内回复、持久开关、静态白名单覆盖、过期/重复/异常请求、并发审核、失败不重试、管理 API 鉴权和邀请恢复。

完整受影响回归为 90 项通过；补充 QQ 号提示和两个边界测试后，相关主人/群接入及实际聊天生成器的 21 项验证再次通过。Python、JavaScript 和 PowerShell 启动脚本语法检查通过。

自动化群邀请测试使用模拟 OneBot。真实私聊和群邀请的进一步验收以用户操作及本机状态记录为准，不能把模拟结果表述为真实群聊已验证。

## 真实群测试与兼容修复

用户已将机器人邀请进入测试群，首次 @未回复。排查确认机器人已入群，但没有可记录的待审核邀请，该群回复开关仍关闭。已通过管理接口为用户指定的测试群开启回复，用户随后确认群内 @已收到回复。

针对该情况，补齐直接入群通知与主人首次 @授权新群两条路径，并增加对应的身份、消息新鲜度和手动关闭保护测试。最终 QQ 桥接、身份/群接入和实际聊天生成器测试共 53 项通过。状态页补充“最近消息过滤”诊断，可区分群未授权、未 @和事件过期，避免只看到服务运行却不知道为何未回复。
