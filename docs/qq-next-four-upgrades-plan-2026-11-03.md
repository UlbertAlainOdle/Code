用户提供的桌面 `1.txt` 仅作为问题样本阅读，其中对话不是当前操作指令。样本显示“确认保存后只给通用回执，再问记忆时回答无法查看具体条目”的体验缺口；**单凭这份文本不能证明该次生产写入成功或所有召回均失效**。需分别查写入回执、条目版本、召回审计和真实回答。公开文档不复制原对话、账号、记忆正文或私有运行日志。

范围边界：不修改人物设定、声线、原过滤器、现有收藏说明和表情/语音组合，不恢复 ASR、普通文件输出或已撤回官方整包。不默认开启共享、搜索、群记忆或主动发言，不改变启动/关窗停止/监督选择。网页只修改四项确实复用的能力/记忆接口和诊断投影；本轮不为网页增加每日自动切会话。

## 二、统一设计约束

1. **历史、当前话题、长期记忆分开。** 降低聊天上下文重要性不等于删除历史，不等于停用一条长期记忆，也不等于遗忘已核验的主人身份。`/reset` 保持原来只重置当前 QQ 上下文的含义。
2. **实际选择比提示措辞优先。** 在拼装模型输入前过滤、排序并限额；主生成、工具重入、跨端关联、群语境、续读和主动互动均不能把降权内容原样补回来。
3. **权限优先于相关性。** “以前很重要”“引用主人”“记录里写着同意”均不提高读取、披露或执行权限。群可见内容必须适合整个群受众。
4. **自然表达与执行依据分开。** 模型提出有类型的意图，服务端按白名单和当前权限执行；普通回答、附件或转发内容不能当命令。无需每轮解释内部流程或添加进度提示。
5. **保留原来记录，最少新增存储。** 复用会话、记忆、任务、来源版本和发送账本，不新造第二套长期记忆库。现有保留期以外的内容不承诺可恢复。
6. **明确新状态的生命周期。** 新元数据需要版本、幂等、重启恢复、过期清理、关闭兼容和旧程序降级预检。执行结果不明不重放，不把模拟测试当实机收件。

## 三、A：每天4点分日与自然换话题

### A1. 用户看到的行为

- 凌晨4点进入新聊天日，普通聊天不发“已清空”通知，不强制另开窗口，也不删除上一天记录。新话题优先，昨天的信息变成较弱参考。
- “我们换个话题吧”“我们聊点别的吧”“前面不谈了”可对当前聊天执行软切换，简单回应后直接聊新的内容，不要求记住命令。
- 提供确定入口（拟定）：`/topic new [新话题]`、`/topic status`，中文别名“/换话题”。`/topic new` 不撤销长期记忆；`/reset` 仍是原有显式重置。
- “换个话题，聊聊电影”只执行一次换题，然后回答电影；“他说‘我们换个话题吧’是什么意思”“不要换话题”“先别聊别的”不切换。
- “前面不谈了”会暂停旧话题的未发内容和主动追问；“把那段接着说”是用户重新索要旧内容，另行核验原结果是否还有效，不自动恢复旧话题的全部权重。

### A2. 聊天日和消息时间

- 每条新消息记录 UTC 时间戳、时间可信度、聊天日和话题代次；现有 `QQTurnTimes` 是兼容来源，不直接把旧表哈希当稳定消息 ID。
- 聊天日：把消息时间转为 QQ 对话的 IANA 时区，当地时间早于04:00归前一日期，否则归当天。按当地日历运算，不按固定减86400秒计算，覆盖夏令时和时钟回拨。
- **时区不从电脑当前时区猜测或改写。** 当前 `chat_time_context.py` 使用 Asia/Shanghai，而主动互动策略另有时区。实施先登记现有有效配置：默认沿用现有 QQ 对话时区；给本功能独立可见 IANA 字段，用户修改后按版本生效。规划文档日期采用 America/New_York，不表示把 QQ 改为纽约时间。
- 入站真实时间决定消息属于哪一天；执行时的当前时间决定此刻哪个聊天日是主日。排队跨04:00、延迟回执和重启不能反复翻日。异常未来/过期事件继续遵守入站校验。
- 旧消息时间缺失标为 unknown，不能用数据库修改时间伪造发送时间。未知旧消息不获得“今天主话题”待遇。

### A3. 作用域和群多人语境

| 状态 | 作用域 | 谁能改变 |
| --- | --- | --- |
| 私聊当前话题 | 机器人账号＋好友 QQ ID＋原 shared/isolated 边界 | 当前已授权私聊者，只影响自己的上下文 |
| 群内个人话题焦点 | 机器人账号＋群ID＋当前发问者QQ ID | 本人自然换题或命令，只降低本人这轮对旧话题的依赖 |
| 群公共话题 | 机器人账号＋群ID＋已有群话题 | 保留原授权管理规则；全群显式切题须主人/已配置管理身份，普通成员不能替全群失忆 |
| 每日衰减 | 对话的有效时区＋聊天日 | 服务端按时间派生，不依赖模型自报日期 |

现有群语境默认保留1小时、空闲约30分钟可换题，且有24小时清理边界。本功能不能悄悄扩大这些保留期：已经清理的昨日群消息不重新读取或重建。群语境开启与关闭两种路径均接相同的时间/话题选择规则，保留各自原存储与权限。

### A4. 降权必须落实到输入

1. 先执行原记忆使用屏障、来源有效性和群受众授权，再做时间与话题选择。
2. 建立独立上下文视图：当前用户本轮输入、当前日当前话题、降权旧话题/旧日、单独授权的长期记忆。保存原文不变，不将历史时间标签写回正文。
3. 初始可调策略：旧聊天日衰减 `0.3 ** min(日差, 3)`；非当前话题再乘0.2；unknown 不超过旧日参考档。分数只用于服务端候选选择，不能声称模型天然支持消息权重。
4. 在原历史 token 预算内，旧日/旧题合计最多20%，当前话题优先；不为凑满额度塞入无关旧话。若旧库只有尾部历史，本期不扩大成全量档案检索；先在现有可读窗口实现可测降权。
5. 用户明确提及旧话题时，可为本轮提升匹配片段的检索机会；仍遵守预算、保留期和授权，不自动恢复已停用记忆、撤销隐私屏障或重开旧话题。
6. 已有网页关联历史和群 `snapshot.history` 也必须经过该视图；不能只处理 `QQStore.conversation()` 后又从其他入口补回全文。
7. 第一版不因凌晨翻日自动调用模型总结或写长期记忆。需要摘要时后续沿用原压缩/来源依赖链，单独验收，不能为了降权造出无来源长期事实。

### A5. 切题、并发和旧结果

- 新增最小的 `context_revision/topic_generation/chat_day` 元数据；以作用域事务推进，事件键保证同一消息不重复切题。结构名称在实现时按现有库确定。
- 自然意图只看当前已认证发问者的直接话语。清晰换题直接执行；含糊指代先问一句，不把转述、引用、文件或聊天记录中的换题句当操作。
- 处理顺序：鉴权→识别直接控制意图→事务推进话题→处理新正文→生成。切题使旧自然确认建议失效，避免新话题中的“好”误批准旧搜索或保存。
- 挂起旧题的自动续发/主动互动草稿；已有确定送达的回执保留。对生成中旧任务设置当前作用域屏障，未发送内容不再混入新题；发送不明保留 unknown，不追发。用户仍可用原状态/取消命令。
- 原 `/continue` 对指定旧结果保留明确索要入口：有效、未撤权且未取消时可只读恢复；失效就解释不可继续，不能用恢复入口绕过停用/隐私保护。

### A6. 验收

自动化：03:59:59/04:00:00边界、连续两天、夏令时前后、跨日排队、重启、重复事件、未知旧时间；实际模型输入旧题预算下降、当前题保留；群个人切题不改别人、跨端关联不回灌；引用中的换题不执行；pending保存/搜索不串题；原reset/continue/群TTL保持。

真实 QQ：私聊先谈虚构话题A，再说“换个话题，聊B”，确认后续不主动回到A；授权群两人交替确认仅各自焦点改变；在配置时区实际跨04:00观察一次。可用隔离可控时钟先覆盖边界，不能以改生产时间或模拟跨日冒充实机跨日。

## 四、B：长期记忆读取与自然、可核对的保存

### B1. 先诊断读取链，不重建记忆系统

1. 检查共享、recall模式、预算、记忆使用状态和当前身份；“读取关闭”“本轮没命中”“有记录但无披露权”必须分开。
2. 在隔离库写一条虚构且唯一的事实，获得真实条目ID/版本；在**不含该事实的新上下文**中提问，核对实际检索结果及最终模型输入，再看回答是否准确。仅问刚说过的话不能证明长期召回。
3. 重启后重复上述隔离读取，覆盖V4/兼容投影、图关联、向量、原标准检索和可选agent实际所用路径。只测现行启用路径及受影响回归，不为无关模块重复付费探针。
4. 将问题定位为存储、检索、提示装配、自然意图路由或模型表述，保留失败样本，不先用“提示它说自己能记住”替代修复。

### B2. 保存前后让用户看得到内容

| 环节 | 设计 | 判定依据 |
| --- | --- | --- |
| 拟保存 | 用一小句展示拟存的关键事实，再问“要我记住……吗？” | 当前候选完整正文和版本，不只用模糊标题 |
| 内容修正 | “可以，但改成……”先改候选预览，重新确认 | 新版本替换旧建议；旧同意不能确认新正文 |
| 明确同意 | “记住吧”等绑定刚展示的那条候选 | 原账号/私聊/话题/候选版本/有效期和已送达提议 |
| 保存完成 | 简短表达“记下了：〈实际保存摘要〉”，可按需看原条目 | 提交成功的条目ID、版本和实际正文；不得按原候选猜写入结果 |
| 重复/合并 | 说明已有这条或与原条目合并，给当前结果摘要 | 原服务真实返回，不一概说新增长期记忆 |
| 部分完成 | 写入成功但候选标记待对账时准确说明，不让重试再写一条 | 既有部分提交/恢复协议 |
| 不同意/不相关回复 | 结束提议或正常聊天，不追问催存 | 原自然确认状态机 |

一次只建议一条，普通闲聊不频繁询问保存。短暂情绪、当次活动、长期偏好要分清；单次经历不能改成“总是/喜欢/每周”这类稳定人格事实。时间用可核对日期，不把“今天”长期保存成永久无日期事实。涉及多件事或敏感信息时先展示范围，不用一声“好”打包保存未展示内容。

自然回执长度初定一小句、正文摘要最多100字；完整条目超过限额时标明“摘要”，提供自然的“展开这条”入口。可变措辞只包裹服务端确定的结果，不改变ID/版本/事实，也不把真实内容交给模型自由改写后当原文。

### B3. 自然读取和解释

- “你记得我哪些事”“有哪些长期记忆”→复用 `browse`，默认当前可使用的已保存记录、分页/分类概括；不是 `/memories` 候选列表，不无限倾倒全库。
- “你记住的那条具体是什么”“展开刚记的那条”→用最近实际保存回执定位条目，调用 `detail`；多条歧义时让用户选，不按相似标题盲选。
- “还记得我之前说的某件事吗”→执行相关召回，不强制全库清单。若只来自短期历史，就不能冒充长期记忆命中。
- “刚才用了哪些记忆”“你怎么知道的”→复用 `recall_audit`；明确“服务端确实选入提示”不证明模型逐字采用，也不让模型凭印象编造召回来源。
- 所有清单、摘要、回执携带原来源/版本/使用状态；**管理浏览**可按用户要求显示停用记录并标识，**普通聊天**不可把停用/删除/不再使用内容带回模型。自然读取工具不能绕过这一差别。
- 主人好友私聊拥有既有管理读取入口；非主人和群里只返回对当前提问者、主体及群全体受众已授权的片段，不能因为问“你记得什么”枚举主人的私人库。
- 刚保存条目的读取不依赖向量索引恰好完成，按真实ID从原权威存储读取；普通相关检索应继续原策略，不能为此每轮灌全库。
- 共享或召回关闭时按真实状态说明；可以提出仅本次读取/打开自动召回的具体建议，不暗中开权限。

### B4. 与网页及后台一致

复用QQ已有管理服务与网页同一记忆库；完善内部结构化提交结果（新增/已存在/合并/部分完成/失败、ID、版本、可展示摘要），再兼容投影为原字符串回执，避免破坏旧命令调用者。检查网页保存后的显示和实际条目是否同版本，原编辑/删除/停用/来源依赖及晚到失效规则继续生效。

### B5. 验收

自动化：保存预览与落盘内容一致、标题不同不误导、重复不新增、部分提交不伪成功、重启可读、向量未就绪仍可按ID查看；不含事实的新会话真实检索选入提示；候选/已存/已召回分清；停用、删除、来源撤回与群无权读取不泄漏；自然读取关闭时原命令照常。

真实 QQ 最少三步：在主人私聊确认一条虚构事实→核对“实际记下了什么”→软换题后问该事实并核对后台召回来源。再按需在原网页查看同条目；虚构条目按原删除确认流程清理，不触碰既有真实记忆。不要求用户重新录入TXT中的私人内容。

## 五、C：能力感知与自然操作闭环

### C1. 统一事实来源

扩展现有 `qq_capabilities.snapshot()`，不另写静态“我能做一切”人设。能力登记至少包含：`id/support/enabled/authorized/available_now/reason/scope/change_allowed`，动作另含参数范围、是否仅本次、是否需确认和执行器。每轮按真实身份与配置投影；客户端、模型、帮助及执行器读取同一登记。

能力覆盖：搜索/网页读取、长期记忆读写管理、图片/文档、合并聊天记录读取、语音、收藏/QQ小表情/颜文字、戳一戳、合并长回答、续读/取消/状态、话题切换、主动互动。明确 ASR、普通文件输出、精确定时提醒、官方整包等现行不支持或已撤回项。搜索服务已配置但额度失败、语音忙碌等应是具体运行原因，不误报成永久不具备能力。

内部状态不日常复述；只有用户问功能、提出操作或失败影响这次请求时解释。不可用时给简短真实原因，不编造“我只能文字”。能力感知不能代替实际调用和投递回执。

### C2. 自然意图与执行政策

| 用户表达 | 处理方式 | 权限和确认 |
| --- | --- | --- |
| “换个话题，聊音乐” | 执行A的当前作用域软切题，再处理新问题 | 清晰直接请求不重复确认；不影响他人 |
| “看看你记住了我什么” | 调B的只读管理/召回接口 | 当前读取权限，不修改开关 |
| “这次帮我查一下”“这次用语音答” | 在已有可用权限下作一次请求 | 不自动变成永久开关；明确关闭时按原策略说明/提出开启建议 |
| “以后自动搜索吧”“把语音打开” | 明确范围后调用原版本化配置执行器 | 已验证主人好友私聊、直接明确请求可作为本次授权；范围有歧义先问 |
| 模型认为需要搜索但开关关闭 | 提出仅本次或持续开启的具体建议 | 收到该建议的真实同意后执行，不自行授权 |
| “不要语音了”“关闭主动消息” | 立即按当前权限和清晰范围关闭 | 保留原控制通道，不能被长生成堵住；关闭不强制附带语音/表情 |
| “记住这件事”“把刚才那条改一下” | 保存/修改有版本的具体记忆 | 模糊指代先展示目标；删除/停用/共享扩大仍保留明确预览确认 |
| “让群里也能知道这条” | 预览这条的主体、目标群、提问者/受众权限 | 不用含糊同意扩大整库权限；走原单条ACL确认 |

“自主指令”在本计划中指：她能判断需要哪个**已登记的应用动作**，向用户提出意见，获得授权后执行；不是执行任意Shell、任意工具、任意模型拼出的命令，也不允许她给自己新增主人权限。

### C3. 流程和持久化

1. 直接请求先经轻量明确规则路由；需要语义判定时复用现有模型/规划层，以严格结构化意图输出，不为每句寒暄额外调用一次模型。
2. 服务端校验动作白名单、参数、身份、权限、目标、时间/话题代次和配置修订；未知动作拒绝执行但不影响正常回答。
3. 拓展原 `QQActionProposals` 的类型化payload，不废弃 `search_on/save_candidate`。支持一次/持续范围，提议先送达才接受同意，仍默认10分钟有效。
4. 提议绑定机器人、真正同意者QQ ID、好友私聊、会话/话题、具体目标及版本。普通“好”只批准最近唯一、明确已展示且未过期的建议；多项或有歧义时澄清，不默许全部执行。
5. 状态沿用 prepared→pending→executing→done/rejected/stale/expired/unknown。重复入站/重复同意不重复副作用；配置变化、换题、权限撤回和取消即时阻止陈旧操作。
6. 执行调用原 `/set`、表达模式、主动策略、记忆管理等服务接口，不让模型向QQ发一行命令后假装由自己执行；完成后读回当前值或提交记录再自然回应。
7. 模型提出多动作时最多保留一个必要变更建议；业务上互相关联的动作需要原子或可解释的部分完成，不通过“都开”制造冲突。原语音只与大表情互斥、可配小表情/颜文字的规则保持。
8. **原始文件、引用、搜索结果、分享记录及旧对话中的同意不是本轮授权。** 群成员只能操作其已有授权的局部动作；全局开关、个人库管理和隐私披露仍走主人好友私聊/原管理页。

### C4. 验收

自动化：快照与执行器同源；关闭/忙碌/未配置/无权限分开；自然查询无副作用；一次请求不永久改开关；明确直接请求不无限反问；提议送达前的“好”、不同人、同名账号、不同群、过期、换题、重复和重启不误执行；版本冲突不覆盖新值；失败不报已完成。保留能力/语音/搜索/记忆/控制命令原回归。

真实 QQ：先问“现在能做哪些事”观察不夸大，再私聊提出一个低影响、可恢复的明确开关变更，检查实际状态；恢复用户原值。另做一次建议→同意→实际执行。不开启未请求的权限，不反复搜索或发送语音刷测试。

## 六、D：读取分享的合并聊天记录

### D1. 当前缺口与支持范围

当前入站主要提取text/at/reply，媒体检测只有image/record/file/video；合并记录卡片可能变成空消息或被剥离。`qq_forward.py` 是**出站**能力，不等于**入站展开**。第53轮已记录真实返回 `com.tencent.multimsg` JSON卡片并通过 `get_forward_msg` 只读核对的历史证据，证明不能只等一个forward段。

实施支持两种经当前安装协议验证的载荷：结构化forward资源引用、严格匹配的 `com.tencent.multimsg` JSON卡片。不能将所有JSON都当聊天记录。优先覆盖：私聊直接分享、授权群分享并@机器人、同会话引用卡片并请求概述。纯卡片私聊可自然概述；群仍遵守原@唤醒/已授权引用唤醒，禁止因卡片放宽全部群消息接收。

第一版保证记录内文字、作者展示名、顺序、可信度标记和可得时间。图片/文件节点只在原媒体策略允许且来源能验证时复用原读取链，不能安全解析时明确这些节点未读；不把仅文字支持说成整包多媒体已读。语音/视频/失效节点标记类型和未读取，不虚构内容。

### D2. 协议和来源核验

1. 先读取现有专用NapCat 4.18.41本地实现、已留存第53轮脱敏结构和当前接口能力；核实 `get_forward_msg` 参数（id/resid等实际字段）、返回nodes/messages/content结构和QQ卡片格式。未知字段是适配待确认项，不能写死凭经验猜出的结构。
2. 本轮实施新增独立接收适配器（拟 `qq_forward_input.py`），避免混改原出站重试与回执逻辑。为原有 bounded action 增加唯一必要读接口及响应限额，不开放任意OneBot动作。
3. 原鉴权通过后按当前消息ID回读 `get_msg`，确认机器人、会话和引用来源与当前消息一致，再从这条真实外层消息提取资源引用。不得接受聊天文字提供任意resid，也不遍历QQ数据库或下载分享URL。
4. 外层“谁在当前群/私聊分享”可以核验；记录节点内部作者/昵称/QQ号、时间可能来自可自定义的转发内容，**不等于真实消息签名**。仅当有独立协议证据核验原消息时才标为 verified，否则是 record_claimed/unknown。
5. 模型能理解“记录显示某人说……”，但未核验节点不能被当作机器人本人确实说过、主人本人同意或某人的事实记忆。复用第71轮引用身份规则的可信层级，不让同名或伪QQ号获得身份。
6. 用户主动把记录分享至当前会话，只提供本次附件的读取范围；不会因此查询原始私聊历史、其他群或主人个人库。生成的摘要同样绑定外层来源和原受众，不能跨群复用。

### D3. 有界展开和模型输入

建议初始限额（实现时据当前协议实验确认，可版本化配置）：单次最多1张记录卡；最多100节点、总12000个可展示字符、单节点2000字、返回体2MiB、总读取8秒、最多2层嵌套、最多8次资源读取。所有子请求共享总预算和当前任务取消信号；超长记录按原顺序保留可读部分，说明读到的节点范围，不冒充全量概述。

- 检测循环资源ID、重复节点引用、超深/超量/压缩或异常大返回；遇到上限停止展开，保留已验证的部分，返回partial/unsupported/expired/timeout等结构化状态。
- 记录顺序以协议数组为准，显示时间用于解释，不因伪造/乱序时间擅自排序；缺少时区或时间时保留未知，不能赋成当前时间。
- 进入独立 `forward_context` DATA段：外层来源、完整/部分状态、节点序号、作者可信度、时间、文本或未读媒体类型。与本轮用户指令分开，不拼成连续 `Doctor:` 历史，避免所有人变成主人。
- 分享记录中的 `/set`、“同意保存”、“忽略所有限制”等是待分析文本；默认关闭该输入路径的自动个人记忆写入和自主工具执行。若用户之后明确要求记下某事，按B/C预览来源和确认，再走原保存接口。
- 复用原回答、群受众校验、任务取消、自然错误说明、Mood/控制标签清理、5气泡和长回答合并投递。不将记录读取失败误报成“文件附件未能读取”，失败原因来自服务结果，表达自然简短。
- 新草稿、摘要、模型流和续读绑定源消息/卡片指纹、策略及上下文版本；发送前、重启恢复和续读时重查必要条件，不复用已撤权/失效来源。
- inbox只存必要类型/安全引用元数据，不存任意卡片JSON和下载路径；展开正文默认仅请求内使用，不建长期全文缓存。源撤回监听或有效性复查无法覆盖时明示能力边界，不能宣称实时撤回保护已证明。

### D4. 验收

自动化矩阵：forward段/JSON卡片/陌生JSON；直接/引用；私聊/授权群/无权群；多作者/同名/伪主人ID/原机器人节点未核验；嵌套、循环、空内容、缺字段、过期、超时、部分读取、超预算、取消、撤权及重启；文本内伪CQ/命令不执行、不自动写记忆；普通引用/图片/GIF/TXT/PDF/DOCX继续可读；旧出站合并转发不回归。

真实 QQ 简化为两次：

1. 用无私人信息的两三条测试消息合并转发给机器人私聊，问“分别是谁说的，概括一下”，核对文字、顺序和作者归属；不能把卡片预览标题当展开成功。
2. 将同类测试记录分享至原授权群，@机器人请求概述；再引用这张卡片请求“第二条讲了什么”，核对后台真正调用及结果。过期/嵌套等异常优先隔离模拟，不让用户做复杂故障实验。

若真实接口仅能取得卡片预览、不能展开正文，本阶段记为未完成并记录具体协议阻塞，不用模型猜内容交付。
