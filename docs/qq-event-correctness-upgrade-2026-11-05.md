# 事件系统正确性整改

本轮承接第120轮整体评审和第119轮操作会话方案。用户已授权整改，并明确正确性优先于节省token；当前DeepSeek仅是实验接入，后续模型可替换。实际测试、部署及真人验收状态以实施进度最新一节为准，本文不作为验收通过声明。

第123轮修订：上下文遗忘以**来源标签继承＋程序统一过滤**为主机制。单件和全部遗忘共用同一依赖校验，不把每次遗忘都实现为整段对话重置，也不常态化增加LLM审核。旧无标签材料才采用下面的保守迁移边界。

第126轮补充：[记忆与话题体验整改总方案](qq-memory-topic-dialogue-redesign-plan-2026-11-05.md)统一自然保存目标、待确认状态和多轮主题上下文，并要求稳定来源早于建卡，以覆盖后续才归档的早期原话和派生回复。保留本文已有权限、事务及有效视图；这项增量仍为设计，不代表125r1已具备全部能力。

## 1. 执行合同

模型负责提出语义计划，主机持有身份、候选对象、范围枚举和执行权。普通回答不能宣告数据库操作成功，模型自由生成的问题也不能登记确认授权。

- 确切命令及本地唯一匹配的明确操作保留确定性入口。语义不清时读取原请求、已送达的登记问题、当前回复和有效候选来源，必要时增加独立模型判断。
- 新语义操作先输出可核对的目标和范围。只有真实送达的问题能承接同一用户、同一会话中的“对的”。问题未送达、换题、另一条机器人提问、账号/会话变化、超过10分钟均不能裸确认。引用真实旧问题须再次核验原目标和权限。
- 确认有附加条件、否定、排除项或改范围时重新定位和预览，不按“对”字前缀批准。没有识别到明确操作或模型失败时不修改，普通对话继续。
- 私聊“忘掉当前所有事件”默认本人保留的个人事件，包括降温、暂停、终态和来源不可用但仍可管理的卡。群内未明确的“所有”先澄清个人集还是本人的群跟进。
- 本人群跟进停止不改其他成员的公共记录；共同取消、完成和删除仍逐卡要求协调人。私人事件不会成为他人可改对象。
- “全部”由主机枚举，预览冻结确切集合。新增、减少、内容/来源变化、权限变化均重新预览，事务内核验并一次提交，不部分执行后冒称全部完成。原聊天和独立长期记忆保留。

## 2. 有效视图和动作版本

个人停止/暂停及删卡需要保留无正文的来源屏蔽身份，使同源群投影无法向该请求者回流。卡片正文、标题、当前决定和日期、摘录缓存、路由锚点、历史引用和待发回答都须使用同一有效来源集合。其他成员仍可使用原先有权读取的公共来源；个人来源自然到期不能等同于本人主动遗忘更长寿命的公共来源。

新增来源保存整条入站文本的摘要身份，以便把事件来源失效关联到原聊天。摘要身份不包含凭据，也不是额外保存一份聊天正文。旧来源只能使用实际存在的来源关联；不能猜造已丢失的归属或补回过期证据。

删除预览使用动作相关指纹，继续核验正文、来源及其到期点、协调人、控制状态和集合。仅active/cooling以及关注统计变化不使删除预览失效；不直接取消CAS，不把到期来源延长到确认期限。

## 3. 召回和模型开销

检索先扫描有效正文，再排序候选，不能只看标题或最后几条消息。回答和路由均优先提供与问题相符的旧细节、作者与关键条件；超过可展示范围时明确材料不全，不能据此声称全体一致。

事件语义操作使用独立结构化任务，最多64000输入字符/4096输出token，30秒供应商请求上限；这只是有界资源保护，不以少一次调用为正确性条件。话题路由允许更多必要正文材料，主回答的用户已保存窗口与预算不擅自改写。未来本地模型可替换决策适配器，主机权限、确认和事务合同保持，当前不切换模型厂家、密钥或运行模式。

## 4. 证据、交付及后续

工程验证必须分开覆盖：同源停止与他人公共记录、历史和派生内容、自然到期、未送达/过期/换题/引用确认、集合变化、语义失败、逐卡权限、事务中途失败及实际桥接入口。模型样例、隔离收发和真实QQ单列，不能互相替代。

本轮核心整改完成后，先做少量真实QQ闭环，不自动遗忘用户现有全部事件。后续维护仍需处理个人32条满额、不可拆的长条件链、降低手动整理负担，以及更长真实讨论的质量和延迟。保留有效分歧比静默丢掉旧条件更重要，不能把“扩大容量”当作已解决自动维护。

原群仅@触发、重要及以上门槛、关系学习关闭、群5/20与来源32、时区、手动启动和监督选择保持；不增加被动群监听，不恢复旧过期证据。

## 5. 第123轮：统一来源标签和传递合同

比较结论：来源标签是主方案；前述有效视图、主机权限与事务合同继续使用。上下文边界用于旧资料兼容，独立模型复核只处理操作含糊等情况，不负责每轮检查是否忘干净。

### 标签覆盖与失效

- 标签位于服务器元数据，不作为大段提示送给模型。原始事件消息、普通答复、主动提醒和派生摘要都受来源约束。记录机器人实际收到的来源集合，不能只相信模型声称引用了什么。
- 原始来源标签绑定事件/证据身份、作者、原到期和内容摘要；普通补充、重要度或热度变化不使仍有效的原话整体失效。表示“当前安排/共同决定”的视图另有语义签名，内容、当前来源集合或控制状态变化时重新读取。
- 回复继承实际入选历史的依赖并去重，历史转述不能清除来源。多个来源混合的回复首版整条失效；仍有效的用户来源和独立事件保留，后续可细化段落。
- 单件停止、暂停、删卡、更正、到期和参与权变化使相应来源及派生消息退出模型上下文；全部操作只是批量应用同一规则。原聊天档案可查看，不因保留档案而允许自动引用。
- 新发言可以形成新的当前话题，不因同名就恢复旧卡或旧事实；模型自己的复述不能成为新建事件的用户依据。

### 所有上下文入口使用同一校验

普通QQ归档重载、桥接近期历史、群历史、明确引用、网页接续材料、主动生成与待发内容都必须校验标签。主动消息生成、排队和发送期间均检查；其真实发送结果和档案保存相同标签。权限/源在模型等待期间变化时不得发送旧内容。

### 旧资料及已污染上下文

旧的无标签材料不能靠相似文本猜造可靠依赖。按已发生的遗忘/失效记录建立持久的保守屏障：缺少可验证依赖的旧上下文不再自动使用，包括已在停止后被机器人重新说出的旧内容；原文件不删除。有可靠来源的原始事件材料、后续新标签消息按其自身状态校验，互不连带清空。

仍允许旧无标签资料的场合，其派生回答必须携带“依赖旧资料”的屏障版本，后续遗忘时一起失效，不能换成无依赖的新记录。恢复一张卡不会自动恢复已经隔离且无法证明来源的旧对话。

### 成本与验收

正常路径仅新增本地元数据记录、集合合并和有效性检查，不新增常态化模型调用；输入减少后可能节省token，但不承诺固定节省比例。使用实际事件来源和已有模型路由，不提高容量或覆盖已保存预算。

必须验证：单件停止不影响另一件的已标记上下文；多来源转述逐代继承；主动提醒在停止后失效；原话补充不误删旧有效证据；更正/到期/成员撤销失效；旧无标签与已污染历史被隔离；实际归档重载和群/引用入口遵守相同规则；全流程不增加额外审核模型请求。真人验收须包含无关普通聊天，不能只检查列表退出。
