### 跨浏览器配置

入口：Settings → **LLM API** 或 **Other API** →「本机配置 · 跨浏览器共用」。Brave输入框仍在LLM API → Search provider。

| 操作 | 实际效果 |
| --- | --- |
| 浏览器配置保存到本机 | 当前浏览器草稿合并到现有 `knowledge_base/api_credentials.json`；默认仅补空缺，不自动替换不同非空值 |
| 允许覆盖同名字段 | 明确允许本次覆盖；仍必须通过读取时修订版本检查，不能覆盖其他页面的新版本 |
| 本机配置同步到此浏览器 | 明确确认后，先备份两个浏览器缓存的完整原字符串，再合并本机已存字段；保留其他缓存字段 |
| 恢复上次浏览器缓存 | 恢复上次同步/恢复前的两组原值；恢复当前值前也先备份，不修改本机文件 |
| 重新读取本机版本 | 更新运行时和保存修订；保留浏览器表单及缓存草稿 |
| 仅保存优先选项 | 跨浏览器共用的本机优先开关，不导入草稿或清空字段 |
| 清空指定本机字段 | 单独勾选并确认；空白输入默认不表示清空；清空模型连接任一项会清空整组key/URL/model |

共16项：模型Key/URL/名称、图片/强逻辑/自主记忆/记忆模型路由、Brave密钥、翻译ID/Key/区域/端点、语音URL/Key/Voice ID/模型。聊天角色、会话、UI外观等浏览器偏好不在此次API配置范围；原QQ17项设置仍独立保存。

本机优先默认开启；已存字段覆盖运行时的浏览器同名字段，包括显式清空值，空缺字段仍可使用浏览器草稿。环境变量的模型三件套和Brave配置仍优先。本机优先关闭后可继续使用浏览器配置。新浏览器读取运行时配置，不会把文件里的密钥自动填入设置输入框或写入localStorage；输入框明确作为浏览器草稿展示。手动同步按钮才会将本机值写入浏览器缓存。

网页普通聊天在请求开始时解析本机配置和路由；QQ仍使用同一凭据解析器。单纯编辑、发送聊天、旧Minecraft轮询不再持久化浏览器草稿。已有受管文件拒绝旧无修订同步端点，防止旧网页覆盖。损坏文件/超时不静默切换浏览器旧凭据；明确清空本机模型后，旧网页请求不能复活缓存Key。

普通状态GET只返回来源/存在标志与非密钥字段。运行时读取及手动同步使用单独的本机同源、管理会话、定制头、POST入口，响应`no-store`；运行时凭据仅保留在页面内存。没有公共导出链接。凭据文件、缓存备份和私有快照均含敏感配置，不进入源码清单或公开报告。
