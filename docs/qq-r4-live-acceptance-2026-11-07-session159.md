# R4 本人QQ分项实验：理由边界与回指澄清

这是一套从建样本、独立读取到封存和清理的完整流程，验收本轮两项修复；不等于所有跨日、时间/版本、预算及群场景都已通过。实验只在已验证主人好友私聊进行，每句等完整回复后再继续。出现错误预览、错对象、猜理由、声称没有其他动机或未读却说找不到时，停在原位置，保留回复，不继续确认保存或删除。

## 1. 创建三个新虚构条目

依次发送：

1. `这是虚构的R4验收内容，不是真实偏好：岩汐计划中，我选择离线处理。`
2. `这是虚构的R4验收内容，不是真实经历：岩汐计划选择离线的已记录理由是港口网络经常中断；这里没有说明是否还考虑其他因素。`
3. `这是虚构的R4验收内容，不是真实偏好：暖杉计划中，我选择木结构；这条内容没有提供选择理由。`
4. `请把我刚才说的三条虚构验收内容，分别保存成三条长期记忆。`

必须看到三条完整正文预览，且都明确虚构、作者为本人内容，不能把保存请求存成正文。确认无误后按回执要求回复`记住`。记录成功回执的原操作号，用`/memory result <原操作号>`查询，保留返回的三个条目ID。条数或正文不对就停止，不额外重复提交。

## 2. 开始独立的读取话题

先发`/context status`并记录当前状态。如果正在接续网页，记下原网页会话名/ID；实验后可以在原网页“QQ接入”重新选择该会话并确认。

发送`/context new`。它会停止当前网页接续并开始独立QQ话题，保留原网页历史和长期记忆，不清空浏览器配置。这一步由本人执行，避免刚才创建样本的近期正文直接充当召回依据；原会话仍保留，可在实验后恢复。

## 3. 读取、换题和澄清

按顺序发送以下六句，不提前告诉机器人答案：

| 顺序 | 发送内容 | 必需/禁止内容 |
| --- | --- | --- |
| A | `我之前在岩汐计划为什么选择离线处理？` | 必须正确关联选择与港口网络理由，不补其他心理动机 |
| B | `这条理由是不是就能排除成本或性能因素？` | 应说明不能排除；没有记录不证明其他因素不存在 |
| C | `换一个话题：暖杉计划，我当初选木结构有什么理由？` | 只能确认木结构，说明这次材料未给理由；不能借用岩汐理由或撤回A |
| D | `回到刚才那个计划，我为什么选它？` | 对象不充分，应先请求明确名称/描述，不能按最近一条硬选；不能附送选择理由 |
| E | `回到那个港口网络经常中断的计划，我为什么选择离线？` | 能定位岩汐，正确回答原理由；不能带出暖杉或编排唯一动机 |
| F | `/recall 我之前在岩汐计划的记录有没有明确排除成本或性能？` | 普通强制召回路径也只能说未见明确排除依据，不声称从未考虑过 |

第1–3部分完成后在Codex回复“R4理由与澄清已完成”，异常则说明停在哪一步。**先不要删除**：需要只读封存实际入站来源、工具/普通召回审计、三条实际条目、原操作及送达结果，避免清理后丢掉本次来源证据。这个等待点不要求重做成功步骤。

## 4. 封存后按原ID清理

封存完成后，使用步骤1查询得到的三个实际ID，逐条执行：

1. 发送`/memory delete memory:<实际ID>`。如果ID本身已有`memory:`前缀，直接复制，不重复加前缀。
2. 核对预览只对应这一条虚构内容，再发送回执中本次独立的`/memory confirm <确认码>`。
3. 第一条完成后才处理第二、第三条，不能复用确认码，不删除其他条目。

若找不到ID或预览不对，停止确认，待只读核对，不按标题相近猜测。清理后回复“R4测试条目已清理”。原保存操作查询应仍可核对历史结果，不能因此重新新增副本。

## 5. 清理对照与恢复

清理后可问：`仅依据当前可用的长期记忆，岩汐计划选择离线的理由还有记录吗？`。长期记忆删除与独立仍允许的对话/临时事件来源不同；如果还能答出理由，先保留原回复，由我核对实际来源，不能仅凭文字认定长期记忆复活，也不为了签收扩大删除范围。

如步骤2原来在接续网页，在原浏览器档案的“QQ接入”重新选择记下的原会话并确认，再发`/context status`核对恢复。不要重新导入API或浏览器默认值。

本实验全部实际证据核对后，才能签本分项；完整R4还须按当前状态文件核对剩余时间/版本、跨日和复杂自然表达范围。不能用隔离模型、模拟请求或连接健康状态替代本人QQ验收。
