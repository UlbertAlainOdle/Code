## 一、目前确认的事实

本轮通过原本机管理接口及只读数据库查看设置和不含正文的统计，没有读取或公布私人聊天原文、账号、密钥和表情说明原文，没有修改开关或模式。

| 项目 | 本次线上快照 | 说明 |
| --- | --- | --- |
| 表达模式 | random，revision 3 | 保留用户当前选择。历史第69轮auto/revision1不是今天的生效值 |
| 指定收藏 | 当前15张，均选中且有语义说明 | 不能将“缺少指定/没有说明”当成此次不发送的原因 |
| 语音策略 | 已开启；最多120字、30秒 | 现在检查的是整份规范文字正文，不是其中适合说的一句 |

样本来自有容量和保留期的缓存，不是过去一周全部聊天，也不能用“没有保留语音记录”证明从未发送过。真实语音输出已有旧真人证据；这次要研究的是自然触发和整体体验。

## 二、问题判断

### 1. 语音与表情少：需要先拆清三个环节

当前链路是先生成完整文字，再做附加表达选择，最后合成/投递。语音要求整篇≤120字，日常回答稍长就失去资格；这与用户希望“根据语义选择声音”的目标存在直接冲突。

表情并非同一个长度问题：代码还会因保存/候选等notes、链接、代码、表格等提前跳过；无自然锚点的小表情/颜文字会省略；random只在模型给出的有效候选里抽取，包括none。不会因为设置random就一定选到表情，也不应强制选到。

现有not_selected信息不足，不能把所有none都诊断为模型“过于克制”，也不能断言协议/TTS坏了。应分别观测：是否有资格→模型选了什么/是否失败→校验为何接受或放弃→是否实际投递。

另一个需要验证的实现风险：当前表达判断只分配256个输出token，却可能返回多个随机候选和正文锚点；较长结构有被截断、解析后降级为none的可能。目前没有足够的结束原因记录证明本批确实发生了此问题，不能把风险当作已确认根因。新诊断应记录finish_reason及结构校验结果，再决定简化返回结构或调整预算。

### 2. 回答偏长：优先补“这一轮需要多少内容”

现有QQ请求主要沿用人物提示、历史和全局输出上限，缺少明确的当轮篇幅目标。关心、解释、复述和建议容易一起出现；长历史也可能让模型沿用此前的长回答风格。

thinking=auto可能影响推理成本和延迟，但仅凭配置不能确定它是冗长原因。直接全局关闭思考不能解决人物反复解释、机械总结或缺少接话空间，也会损害复杂问题。

## 三、优化设计

### A. 先记录真实触发漏斗，不保存聊天正文

每个逻辑回答记录固定枚举和长度：

1. 消息类型/当轮篇幅策略、正文长度、预期气泡数、实际气泡数。
2. 语音候选是否允许：关闭、明确文字偏好、忙碌、长度、不适合朗读等原因分开。
3. 表达选择：主动none、无匹配收藏、选择器超时、接口失败、JSON不合法、ID失效、锚点不合法、random选到none等分开。
4. 真正投递：已确认、取消、权限变化、合成失败、协议拒绝、结果不明。选择到语音不等于收到声音。

只存枚举、计数、时间与版本，不记录原问答、模型思考、密钥或媒体URL。使用有上限的元数据账本，展示采样范围和缺口，不靠无限保留正文分析聊天。

### B. 让回答长度随话题变化

篇幅策略与人物设定分离，作为当轮约束，不重写人设。初始目标用于引导和评估，不在固定字数处硬截断：

| 对话场景 | 初始目标 | 行为 |
| --- | --- | --- |
| 招呼、简单确认、轻松接话 | 约10～60字，通常1气泡 | 接住一句，给对方继续说的空间，不自动展开建议清单 |
| 日常分享、情绪回应 | 约30～120字，通常1～2气泡 | 选最重要的一点回应，不每次“复述＋分析＋安慰＋建议＋总结”全套 |
| 明确的一般问题 | 约60～220字，通常1～3气泡 | 先回答所问；只有确实帮助理解时补充 |
| 复杂推理、步骤、用户要求详细 | 按需充分展开 | 保留必要细节、代码/表格和原长回答机制，不为了短而漏答 |

同样一句“今天好累”可能只是想聊天，也可能在求具体帮助，要结合直接问题、当前话题、关系与心情判断。不能仅按字符数或固定关键词分类。

在auto思考档位下，简单接话可选低推理成本，复杂任务沿用合适档位；用户显式设定none/high等时保留其选择。篇幅目标单独控制，即使需要认真思考，也可以只给简短结论。

每轮输出预算在原总上限以内分配，8192仍是复杂回复可用的上限。优先通过当轮组织方式和停止条件减少废话，不用截断造成半句话或假装回答已经完整结束。

### C. 先决定表达意图，再生成合适载体

保留原语义与心情选择，改变“长文完成后才找装饰”的顺序。内部区分：纯文字已经足够、声音有表达价值、某张指定收藏适合、小表情/颜文字适合。

- **语音不再以整份文字≤120字为唯一前提。** 若声音适合，可生成一小段有表达价值的朗读正文；仍遵守原语音120字/30秒、声线、取消和回执限制，不为增加频率放大整段音频。
- 文字较长时，语音可以承担一句安慰、招呼或强调，不机械朗读整篇，也不额外重复一大段相同内容。若找不到自然、准确的声音内容，就不发。
- 明确“发点语音”且本轮可用时，保留已修好的明确意图路径；不可用要给具体原因，不能回到“我只能文字”。
- 收藏按主人指定说明与语境匹配；不因为没匹配到大表情就补笑脸。技术说明、严肃陈述、纯操作回执允许完全没有附加表达。
- 每轮最多一种视觉表达；语音只与大表情互斥，可配自然内嵌的小表情/颜文字。沿用原正文锚点和语音清理，不朗读表情符号或内部标签。
- 充分利用现有心情和逐人关系，只调节自然语气、亲近感和回应意愿，不能让“亲近”变成每次必发语音或爱心。

不按“每三次发一次”、固定百分比或收藏→小表情→颜文字回退来制造热闹。也不直接把none候选删掉。

当前random选择会增加表现不确定性。建议在隔离对照里比较“现有random”与“单次语义裁决auto”；只有实际更自然时再给出切换建议。本轮不擅自更改用户当前random/revision3。

### D. 减少分离判断带来的延迟

尽量将当轮篇幅和表达意图并入同一次生成的内部结构化结果，或复用已有判断；不为每句闲聊串行新增多个模型请求。内部结构在服务端验证，不把JSON、Mood或控制标签显示给QQ，也不改坏现有过滤器。

先限定QQ路径；普通网页的流式显示、人设、原语音生命周期不因QQ结构化适配被重写。解析失败保留可用文字，附加表达失败不导致重复发送整份回答。

## 四、如何证明明显提升

### 1. 建立可重复基线

冻结代码、人物/声线、模型、搜索/记忆状态、表达目录和设置版本。先补原因统计，再按相同输入、相同可用资料和相同预算生成基线。

准备48个虚构场景，六组各8例：轻松接话、情绪分享、一般问答、需要详细的复杂任务、明确语音请求、明确禁止额外表达。包含同一句话在不同上下文/心情下的变化，不能只有预先挑好的成功句。

将当前版与候选版结果打乱，隐藏版本名称。使用独立评分和人工抽检，不能由生成答案的模型只给自己的版本打好评。保存全部失败和退化例，公开报告只用虚构样本。

### 2. 预先写清判据

| 维度 | 对照指标/目标 |
| --- | --- |
| 简单聊天篇幅 | 轻松接话和日常分享的中位长度目标下降至少30%；这是待验证目标，不是当前已达结果 |
| 内容完整性 | 同时比较是否回答所问、关键事实遗漏和复杂任务质量；不能用少说内容换取“变短” |
| 自然程度 | 机械复述、无请求建议、模板总结、不给接话空间的次数下降 |
| 语音与表情 | 在预先标注的合适场景中更容易正确选择，非合适场景不增加硬塞；不追求所有聊天都有媒体 |
| 明确意图 | 可用时明确语音请求应进入真实语音投递路径；明确不要语音/表情时不得发送；不可用及失败需正确归因 |
| 组合与发送 | 大表情与语音不同时出现；小表情/颜文字不被朗读；同一回复没有重复执行或重复补发 |
| 延迟 | 记录首个可见气泡与整轮完成的p50/p90；不能靠增加多次判断把短聊天反而拖慢 |
| 人设与隐私 | 人物定义、原过滤器、权限、声线和用户设置保持；回执不进普通聊天/学习链 |

### 3. 分开验证四层效果

1. 确定性自动测试：策略、预算、组合、失败/取消/解析降级和关闭兼容。
2. 真实模型的虚构对照：篇幅是否贴合话题、媒体选择是否合理；模型输出选voice不代表音频已合成。
3. 隔离本地TTS与协议测试：实际短语音内容、时长、非静音和真实回执契约，不改用户声音。
4. 少量真实QQ收件：在原授权范围用简短自然聊天核对显示和听感；需要用户协助时给一两个简单步骤，不安排复杂多端联合任务。

不把旧“明确请求收到文字和语音”签收扩大为当前自然触发通过。不把本轮七项功能的代码回归数字当作体验优化成绩。

## 五、执行与回退顺序

1. 收尾七项首版的源码验证和部署状态，保留原设置和新的默认关闭策略，不同时重构人物/记忆/声线。
2. 完成表达漏斗统计，采集明确标注范围的基线，确认none究竟从哪里产生。
3. 先做动态篇幅引导与思考档位分离，对照证明简单聊天更简洁且复杂任务不退化。
4. 再做可独立成句的短语音意图、语义表情选择和合并判断，验证延迟和媒体效果。
5. 出具对照表、虚构失败例和真实收件边界；达标再按明确选择启用，未达标保持原运行策略并指出退化项。

体验策略有总开关及独立concise_replies/short_voice分项，旧页面只保存总开关不重置分项。分别关闭可回到原篇幅流程或整篇短语音门槛。第77轮另确认并修复random只按视觉kind/id去重会吞掉独立语音候选的缺陷，此修复和诊断独立保留，不因体验开关关闭而恢复缺陷。不覆盖最新聊天、表情目录或用户后来修改的模式。后台管理面板正常关窗停止、原监督及Windows自启动选择保持。

**当前结论：**篇幅试用版不硬截字，按话题完成一个回应意图后停止，目标调整为短接话通常≤25字、分享通常20～50字、一般解释按需80～180字，复杂任务保留充分细节。正式数据支持“简单聊天更短”，尚不支持“整体更自然”；早期错误夹具结果及负面评分均保留，不作通过证据。短句语音有96份真实选择计划、19份原文片段校验、一次真实本地TTS及独立开关/取消/回执专项支持；真实QQ收件仍单列，不以测试数或计划voice冒充。实际保存状态及下次启动入口见第77轮报告。
