# 第115轮：满额群话题的可预览子话题整理

日期：2026-11-05，America/New_York。开工承接114轮542项清单，全部指纹一致，189份原测试文件未改。原入口已恢复后端和监督进程，仍保持QQ手动启动、NapCat持续监督关闭；观察正常恢复采样并如实增加为19个已存缺口，原起点及unknown不重写。

本轮落实满额后的一个安全出口：不扩大每卡32条有效来源，也不自动删除有效观点、异议、条件或承诺。由明确指定的协调人选择原话来源并指定独立子话题名称，先完整预览，再确认搬移。原话题腾出相应槽位；新卡占原有群20条总量中的一条，初始降温，不额外占活跃名额。此功能是显式整理，不是无限追加或自动语义压缩。

## 操作与行为

1. `/events group show 原话题编号` 核对来源编号。
2. `/events group split 原话题编号 来源编号,来源编号 子话题名称` 仅生成预览。
3. 核对预览中全部原话、作者及影响范围后，发送 `/events group split-confirm 确认码`。

在群内仍须真正@机器人。重要及以上好友私聊管理群话题时，仍需原有实时群成员核对；命令不会借拆分绕过参与权。预览只绑定当前账号，10分钟有效、全局256条上限；绑定原卡完整版本、原策略、停止设置和当前身份/成员版本，确认时在同一SQLite事务内重查，任一变化拒绝旧预览。

一次选择移动完整来源，不截取或改写句子。某作者存在承诺、退出或进展链时，将该作者当前有效来源整组列入预览，避免只搬走承诺却留下退出，或反过来恢复旧承诺。完整预览超过5000字时拒绝，不用省略预览授权未展示的内容。正式及历史决定留原卡；原卡须留下有效来源，不支持整卡搬空。未指定协调人、同名子话题、来源失效或容量不足时均不写卡。

确认后保留原贡献编号、作者、原话、消息来源和观察时间；同源证据索引改指向新子话题，个人投影正文保持，114轮同源更正/撤回可继续追到新位置。原卡revision增加、归纳缓存失效，旧待发按版本拒绝。其他成员的停止设置完整继承到子话题，整理不能代替恢复跟进。

拆出的旧来源记录版本化的原有效到期点，既不因移动而刷新，也不被子话题后续热议或查询续期；原expires字段不追溯改写。新贡献仍按现有生命周期。子话题名称明确标为协调人指定的管理名称，不冒称成员原话；原卡只保留最近32个无正文子话题编号关联，删卡不会在原卡残留其标题副本。

子话题独立管理：不会自动继承原共同决定，删除/完成/取消其中一张卡不自动作用另一张；这一点在预览和回执明确说明。整理后请使用子话题的新名称接续。直接对原满额卡继续新增仍会拒绝，并给出可信的未写入说明和整理入口，不能由模型声称已全部记住。
