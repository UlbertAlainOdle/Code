## 本轮交付

| 功能 | 行为与边界 |
| --- | --- |
| NapCat专用进程守护 | 只接受当前工作区`.runtime/napcat`内已安装的程序与profile。验证可执行文件、工作目录、专用环境、PID与创建时间；不接管日常QQ |
| 现有进程接管 | 找到唯一专用主进程时只记录所有权，不重新启动；多实例、陌生profile、无权限确认或其他进程占端口时停止尝试并显示原因 |
| 有界恢复 | 原主进程退出后10秒缓冲，仅清理此前记录且重新验证过的残留启动器/子进程；发现主进程重新出现立即停止清理，不终止活跃QQ主进程 |
| 重试持久化 | 2秒起步指数退避、上限60秒，连续失败最多5次；预算跨守护重启保存。显式关闭再开启以新的修订重试，避免快速往返版本丢失 |
| 人工停止保护 | 全局停止/维护意图与启动/清理共用锁。暂停NapCat守护仅停止自动恢复，保留现有QQ及登录；登录失效不靠重启解决 |
| 网页开关与状态 | Settings→QQ接入→后台守护与在线观察。独立CAS保存，不混入原17项QQ配置；只允许本机同源管理。CLI与网页读同一策略 |
| 在线观察 | Saya守护每分钟采样。仅固定状态字段，不保留账号、路径、Key或聊天；最后100次状态变化，有效区间与未知时段分开 |
| 观察准确性 | 超过90秒的采样缺口不算在线；当前中断尾段显示未知；时钟回拨不重复计时。达到24小时也仅进入人工审阅，不能自动填PASS |
| 网页排空保护 | 停止时同时检查QQ任务和正在执行的网页写请求；SSE计数贯穿整个响应体。阻止新写请求，现有流结束后才允许停止，恢复后重新接收 |
| 自启动验收 | 新增Validation临时任务与无副作用执行入口，真实注册→运行→撤销通过；正式用户登录自启动仍关闭 |
| 旧入口兼容 | 已安装的`.runtime/napcat/start-all.ps1`转发到共同启动入口，避免与新守护各自起进程；原私有脚本备份保留 |

新NapCat开关默认关闭，本轮网页开启/关闭往返后也恢复关闭。后端Saya守护和观察继续运行。开启NapCat守护不代表开启Windows自启动，两者独立。

## 自动与本机验收

- 最终累计 **228项Python通过**，8个既有FastAPI弃用警告；原212项全部保留，新增16项覆盖上述功能。证据 `.runtime/qq-upgrade/session2-release-junit.xml`。
- JS聊天与思考回归 **10项通过**；QQ设置JS及5个改动PowerShell文件语法检查通过。
- `test_qq_napcat_supervision.py`：路径约束、原有进程接管、PID复用/错误profile拒绝、人工维护不启动、陌生端口、失败预算及真实辅助进程退出恢复。辅助进程是临时Python，不是实际QQ。
- `test_qq_transport_recovery.py`：真实本机TCP模拟OneBot，区分未登录、在线、401、断开、重连；未断开电脑网络。Windows连接拒绝可能先触发外层超时，两种结果都不得保留之前的登录成功状态。
- `test_qq_observation.py`：缺口、回拨、隐私白名单、有限事件、24小时仅需人工审阅、原子保存失败；模拟一天不冒充真实一天。
- `test_qq_service_controls.py`：鉴权、同源、CAS、暂停时可读、坏私有状态不泄漏。
- `test_qq_service_drain.py`：真实ASGI流先发送头/首块再挂起；维护看到活动流1，拒绝新请求；旧流正常结束后归零，再恢复接收。
- 两个PowerShell脚本实测：临时Validation计划任务注册/执行/精准撤销；隔离副本中验证缺失意图、人工停止、维护、坏JSON、运行意图与ValidationOnly，未启动真实QQ。

## 部署与网页实测

维护窗口更新Saya及守护，机器人专用QQ进程没有退出或重新登录。原17项设置、继承、共享默认、群授权与凭据摘要前后一致；没有向真实QQ发送测试消息，没有付费模型探测。

网页开启NapCat守护后状态变为“专用进程运行中”；实际只有一个原有专用主进程，账号匹配、失败数0。再关闭后当前QQ及登录继续运行。私有证据 `session2-live-deploy*.json`、`session2-live-napcat.json`、`session2-settings-service.png`；截图不展示私有会话。

在线观察从本轮部署后开始，不补算此前运行时长。维护启动区间可能记为非健康，采样缺口记未知；不能用当前运行状态覆盖历史记录。
