# QQ渠道适配与内部标记审查（第十六轮）

2026-10-28，Asia/Shanghai。针对用户报告QQ回复以`[MOD_SAYA: affectionate]`开头，审查生成提示、最终正文、旧历史、分段/续读与传输边界。保留原人物设定和当前设置，不拓展到QQ-04。

## 原因与处理

1. 原有清理器只认精确的`MOOD_SAYA/MOOD_USER/MOTION/MC`写法，漏掉实际出现的`MOD_SAYA`；大小写、全角符号及残缺标签也存在类似缺口。
2. QQ复用网页提示，仍含“必须生成MOTION”的指令及风格中的动作标签要求。现通过仅服务器可设置的QQ参数移除内置动作指令后缀与标签格式要求，保留人物前缀、风格、依恋、社交和记忆想象规则。网页默认参数和动作功能保持。
3. QQ共享私聊原本还带入外部游戏状态，虽然已有命令执行隔离。现不再注入游戏状态，且QQ不生成网页动作事件/抽取动作建议；游戏命令执行隔离仍保留。
4. 本地模型旧分支还会注入网页全局`DoctorEmotion`选择。现QQ不读取此网页状态，避免混淆当前发送者的情绪；原网页选择、人物设定及会话情绪连续性不改。
5. 统一QQ输出过滤，覆盖真实生成器完成/中断存档、SSE适配、旧格式、新分段及最终OneBot发送；来源开关不会绕过。识别应用的已知协议与实际错拼，不泛删任意括号、来源编号、URL或普通文字。
6. 旧助手历史只在本轮输入投影中清理；原文件不回写，用户原消息和引用归属不变。旧待发续读段在发送时过滤，原结果编号、顺序和已发送回执不重写、不重放。
7. 额外保护意外混入最终正文的`<think>`块，包括其中包含代码的情况。正常讲解协议的反引号/代码块、公式保留。纯内部标记没有正文时给出简短无正文提示或原有生成失败回执，不把内部标签发出。
