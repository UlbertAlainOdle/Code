# 第120轮：事件系统整体评审与收敛顺序

日期：2026-11-05，America/New_York。当前业务117r2，119轮多轮确认/批量遗忘仍为设计；118轮自然遗忘后缀失败未修。本轮按用户要求整体评审，不实施修复。开工119轮557项指纹一致，323项业务/测试冻结、191份测试文件保持。

## 1. 结论与成熟度

框架有价值：用来源可核对的临时话题支持跨会话接续，保留作者立场、共同决定与独立长期记忆的区别。当前成熟度不均衡，来源、权限、写入校验和部分失效保护较完整；自然语言操作协议、跨路径一致性、旧细节召回和长讨论维护仍不够完整。不能把设计文件列出的能力算成已经上线，不能以单点回归数量替代完整使用流程。

较扎实的部分包括真实账号归属、本人贡献修改边界、指定协调人共同定案、原话/来源/版本核验、部分同源更正及缓存/待发失效、有限容量与失败不伪称保存。已有真实短例和隔离验证各有明确范围；这不等于所有控制、删除和资格变化组合均已签收。

## 2. 本轮三个隔离复现

均使用项目现有虚构测试桥接器、临时数据库、模拟模型结果及NETWORK_GUARD，没有使用生产事件、真实QQ传输或提供者请求。以下是工程隔离复现，不声称已经在用户真实QQ账户重现。

### A. 个人停止后，相同来源可从本人群参考进入

同一发言进入个人/群两处。停止个人卡后，个人recallable为false，回执表示已停止本人各会话自动使用；但同一请求者的群参考仍包含该同源原话。原因是个人控制和群读取分别判断，个人停止没有完整落实到群参考的面向请求者过滤。

这是应优先处理的一致性缺口。修复不能删除所有人的公共群记录，应让该请求者的有效视图统一排除已遗忘来源及其派生标题、日期、摘要和历史引用，其他成员仍按自己的权限读取。批量遗忘必须复用这一完整链路，否则可能操作成功却继续自动提及。

### B. 有效旧正文细节缺少稳定召回入口

群卡保留六条有效来源，早期来源具有标题中没有的独特对象。超过普通群窗口后，该来源仍在新生命周期卡内有效，但按这个对象提问时，群事件context为空，路由候选的最近三条与四条公开锚点也没有该对象。

事件路径存在存储与召回不对齐。其他上下文可能偶然补足，因此这不证明整段聊天必然答错；应补正文/作者/关键状态索引和按问题取证，避免只按标题、近几条及更新时间选材。继续放宽采集或增大容量不能解决这一问题。

### C. 自动降温导致原删除预览失效

在来源、协调人不变且确认仍未超时的前提下，仅自动active→cooling就增加整卡revision，确认被按旧版本拒绝，卡未删除。这是保守整卡CAS带来的交互成本，不是越权删除。

后续需按动作区分影响执行含义的版本：权限/来源/目标范围/正文变化必须重新核验；纯关注分数和降温状态变化不应一概使预览作废。删除仍须保留完整来源/范围校验，不能直接取消CAS。此建议尚未改动119轮已记录的严格快照规则，实施前需细化合同和反例。

## 3. 其他已知缺口和设计风险

- 自然操作还依赖规则和字面对象，已有后缀拒绝的真实案例。119轮语义解析和有送达绑定的多轮确认尚未实施；不能只修几个关键词，或把“对的”作为脱离上下文的执行信号。
- 话题身份仍需要稳定处理同名新一轮活动、泛指接续和交错讨论。标题及最后一张卡只能是线索，不应单独授权合并、改写或结束。
- 普通讨论、待办、明确日期活动对完成/过期的含义不同。内容状态、关注程度、用户是否允许自动使用、是否有任务结果需要分清，避免给每个随口话题都套任务完成流程；同样不必为每个维度再调用模型。
- 32条满额后明确拒绝和协调人拆分提供安全出口，但依赖用户看编号、挑来源、确认新卡，不能作为长期自动维护的终点。个人满额及不可拆的长依赖链/决定仍未解决。
- 当前摘录式归纳保留来源和限制，但不能无损压缩无限独立信息；条件过多时还需按当前问题选取关键证据。真实长讨论的质量、延迟及总usage仍缺更广对照，不能仅以字符变少判成功。
- 管理拒绝只说“请明确”不足以解释是目标不匹配、多个候选、权限变化、内容变化或来源过期。应提供可核对的简短原因，普通聊天不被错误回执替代。
- 旧误操作不应自动恢复，但需要可授权的纠错路径。新的最小操作前后状态审计有助于纠错；不能用“继续聊”自动重开真正已完成或取消的事件。

群仍仅观察原已接收/@范围。未@讨论未被观察到是现有明确边界，不将其视为可以自动打开监听的理由。

## 4. 建议简化和统一的地方

1. 统一“原始来源→当前状态/关系→面向请求者的有效视图→回答/管理”接口。停止、删除、改写、降级、群参与撤销和到期都通过同一有效视图，不能由每个模块分别猜可用性。
2. 所有自然操作、明确命令、单条与批量均进入同一受限执行器。模型只提议动作与指向；主机核验并执行，输出真实回执。保留命令作为确定性入口，不让用户承担内部模型分类职责。
3. 将操作所需的内容/控制/范围版本与自动关注统计分开，按动作检查必要依赖。这样可以保持安全，又减少没有实质变化的重复确认。
4. 对用户默认只展示容易理解的跟进状态与当前有效内容；重要度、热度、置信度、版本和来源放在解释入口，不要求用户记住所有内部名词。
5. 按“进展→更正→查询→遗忘→后续普通聊天”“澄清→对的→执行”“一批事件→预览→变化→确认”等完整路径评估；少数模型样本和独立函数通过不足以证明闭环稳定。

## 5. 优先级

- P0：统一本人遗忘的跨投影及派生内容过滤，补停止/删除/资格变更完整依赖矩阵；与真实后缀拒绝一起作为管理闭环的基础。
- P1：落地119轮语义操作及多轮确认；在批量操作前复用统一执行器和过滤链。细化动作相关版本，避免持续讨论中反复确认。
- P2：补有效正文/作者/关键条件召回和按问题读取，区分“未采集/未整理/已过期/未召回/明确遗忘”。
- P3：降低长期维护对手动拆分的依赖，处理个人满额及长依赖链，再做更多真实长话题质量/成本对照。

优先完成这些闭环，再增加新入口和更宽自动化。本轮只有评审与三个隔离样例，没有修复业务、真实事件或配置，未重跑不变332回归，也未重启服务或操作观察台账。
