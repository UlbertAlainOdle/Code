# QQ 心情元数据、每日记忆与操作台

日期2026-11-14，America/New_York。用户明确授权在离开电脑期间推进已确认工作；本轮在说明实施范围后新增本文件，旧第200、201轮文件保留为历史。当前部署及最终结果仍以实施状态最新入口为准。

## 用户确认的规则

- 原有日记忆/DayState保持原样，不修改其计数、读取窗口、遗忘或清理。
- 新每日记忆仅针对人的私聊。当日内容持续整理为一份待保存稿，不逐句建条目、逐句确认；按已保存QQ时区每日24点结算，不沿用旧话题系统04:00分日，也不按执行主机纽约时区切日。
- 日终待确认内容等主人回来批准，待批期限为日终起三天；逾期清除草稿正文与来源，不自动入库。界面队列持久保留待批状态，不以机器人登录冒充主人在线，没有新增半夜QQ催批消息。
- 其他人的私聊也由主人批准，仅每日低门槛路径；不生成其他人的高门槛重要记忆，不建立群每日记忆。
- 主人的重要内容可单独待批。待批重要项继续吸收关联补充；已保存的重要项及其他符合权限的旧条目，后续相关对话进入原编号的维护提案。确认前不覆盖已保存内容，确认后保留版本，下一次变化可继续维护。
- 重要项与每日稿覆盖相同来源时先决定重要项；保留后从每日稿移除覆盖来源，拒绝则每日稿仍可保留。旧已批准条目的内容若只是重复，不应再产生保存。

## 心情漏解析的根因与处理

旧解析器仅识别MOOD_SAYA；实际MODAL拼法既可能漏到QQ，也无法驱动该轮标签解析，不能据此称整个系统永久失效。原第200轮过滤继续作为出站兜底。

本轮QQ正文不再被要求携带内部心情标签。原八维心情仍作为语气参考；回答正文完成后，使用独立、无人物/历史/工具注入的有界JSON任务提取实际回答语气，主机只接受既定枚举。元数据单独推进原状态，再服务语音和表达。原网页默认标签合同不变。

失败、截断、无效JSON、非枚举值不假装成neutral更新；保留原状态，取消继续传播。锁定不请求分类。提取有四秒上限、96个输出token上限，逐次请求记原用量账本；失败不重发正文。QQ另保留有界、无正文的提取状态诊断，失败不重置上次成功状态的闲置计时。仍不声称模型永不产生任意异常文字，代码字面量保留规则未扩成全局关键词禁令。

## 表达选择

表达选择改走既有独立JSON任务入口，避免普通角色生成链干扰格式。原random模式、语音/短句语音开关、收藏内容、拒绝、字数/时长、互斥、冷却及不明发送不重发均保持。不以强制比例制造活跃；修通技术路径不等于自然使用频率已经验收。

## 每日稿和全库维护

新增队列不是第二个长期事实库：待批正文不参与长期召回。批准调用原KnowledgeBase、写入账本、CAS、原生V4与证据版本；未知结果查原操作，不重建请求。日条目记录原对话日期，来源记录原入站时间，不伪造为批准当天发生。

普通私聊启用新策略后，原逐句候选流水线关闭；不支持自动整理的引用、转发或附件也不能偷偷切回旧自动询问。显式保存、原命令和既有已送达确认合同暂保留兼容路径；它们尚未全部迁入操作台，不能称QQ所有操作回执已移除。

维护候选按同一个人的原内容相关性选取，原编号/版本由主机限定，不由模型自选任意库对象。包含疑问、猜想等内容不能据此改写重要项；停用、锁定、托管槽、归档、项目范围不匹配、秘密及超出完整读取预算的条目排除。既有库中的合格旧条目也参与，而非只维护本轮新建条目；不会脱离新对话批量重算或改写全库。其他人的后续内容仍走其每日路径。

独立重要稿从创建起同样采用三天待批上限，更新不无限延长到期。每份稿最多32条直接用户来源、2000字；同一对象最多16份活跃稿，总待批最多512份。容量或分类失败有内容无关计数和操作台提示，不默默丢掉旧来源、硬截正文或冒称完整收录。更长条目需要明确保存/原管理入口处理，不能凭截断原文生成覆盖提案。

草稿依据是已认证入站并已完成回答投递的用户原话，不是助手解释或旧事件投影。普通无关记忆编辑不应抹掉原用户陈述；草稿保留直接来源的停止屏障，历史遗忘边界和显式来源停止仍使其失效。原事件、缓存、生成与出站的权限/版本/停止校验没有放宽。未批草稿拒绝/到期/失效后清除其正文和来源；保存后证据进入原长期记忆及版本体系。既有备份、原聊天和审计按原规则保留，不宣称抹除一切副本。

## 操作台

本机入口为`/static/qq-memory-console.html`，也从QQ设置页进入。支持今天整理中、等待确认、最近操作，完整正文与来源预览，确认/不保存，以及有界查询输入。账号来自原本机同源管理会话及已配置主人；不能通过浏览器请求伪造QQ作者、来源或共享会话。确认绑定实际预览版本；来源变化、目标版本变化、权限关闭、过期、重启或部分失败不能变成重复新增。

此入口目前处理新每日/重要/版本维护队列，并支持已登记的长期记忆只读查询。旧候选队列、所有显式保存/删除/归档指令的完整迁移及全部自然语言操作尚未交付，不把有限输入框描述成无限制命令执行器。主人回来后在操作台审批，不依赖不可靠的QQ在线状态推断。

### 批准后的个人隔离

他人的已批每日条目进入`qq_person_<bot>_<subject>`内部个人命名空间，复用原有项目作用域围栏，没有创建用户项目或群。原V4与旧检索的主人默认范围都不包含它们；不能仅靠待批列表分开或提示模型“别弄错人”。主人仍可在管理入口查看和审批。

对应联系人在自己的私聊中，只能只读引用其本人、同机器人、主人已批准、当前仍可用的条目，受原条数和token预算约束。不会开放主人全库工具，不把联系人变为主人，也不向群提供该私聊内容。生成和送达再次检查身份、当前版本及纪元；私聊历史、缓存续读和戳一戳沿原纪元边界过滤，关闭策略时旧派生缓存失效，原聊天及已批准记忆保留。相应回滚兼容标记单独记录，不能回到不认识这道围栏的旧版本。

## 实验和验收标准

| 实验 | 必须通过 | 环境与证据要求 |
| --- | --- | --- |
| 原标签与新心情结果冲突 | 新状态只由独立、校验通过的元数据决定；出站正文无控制标签 | 原生成器、隔离模型传输和实际状态存储，不只单测正则 |
| 元数据错误/锁定/取消 | 错误有诊断且不伪更新；锁定不请求；取消不吞掉 | 无效字段/JSON/枚举、HTTP失败及取消专项 |
| 表达与短句声音 | 有效JSON通过主机规则，选定语音逐字对应完整原句；拒绝时不发 | 真实模型选择与隔离发送分开，真实QQ听感另验 |
| 当日多话题和改主意 | 每人一天一稿、保留变化与否定、无逐句询问、无未批长期写入 | 原响应器与消费者，检查实际账本和投递 |
| 切日和离线 | 保存QQ时区00:00结算、跨日不混稿、重开不重复催批 | 可控时钟含时区/DST；不代签真实跨夜 |
| 三天与拒绝 | 到期/拒绝后正文与来源确实清除，不自动保存 | 检查队列表，不仅检查页面隐藏 |
| 主人审批其他人 | 草稿隔离、确认者仅主人、不建其他人重要项/群日稿 | 身份/本机认证/跨账号反例 |
| 重要项连续变化 | 待批原项更新、旧预览拒绝、已保存后下一版仍可维护 | 原CAS、版本、原编号及重新读取 |
| 重要与每日重叠 | 审批顺序不能造成两次写入；拒绝重要项后日稿仍可决定 | 正反顺序、来源覆盖与重复确认 |
| 已有库维护与历史 | 不另建重复事实；真实安排变化与事实纠错的历史读取界限不变 | 原V4来源/版本、停止和遗忘回归 |
| 故障/权限/容量 | 结果不明不重放；关闭原保存/共享时不继续采集；上限不被摘要绕过 | 确认后回包丢失、预览变更、源失效、32来源/总量限制 |

陪伴体验须另作当前/新流程的同条件比较：每百轮普通对话的主动确认数、控制气泡数、重复候选数，以及主人在操作台的处理次数/耗时；同时核对遗漏、误存、等待和API用量。普通聊天应不主动出现命令、确认码、编号和候选询问；明确操作请求仍需真实说明结果。不能仅隐藏QQ提示，转而让主人处理大量队列后宣称成功，也不以表情/语音数量变多作为单独通过条件。

真实跨夜、实际三天未批、自然重要性阈值、语音听感及主人是否感到打断减少，需要后续自然使用观察；模拟时钟、隔离OneBot、实际模型和实际QQ必须分别记录，不相互代签。最终测试命令、失败尝试、冻结清单、部署与剩余入口见实施状态本轮记录。

## 已执行的模型与页面实验

三组隔离实验调用当前配置的实际模型，共19次请求、接口报告17,977 token，失败及未知用量均为0。第一组7次覆盖日稿、日内修订、重要项连续补充、已有库维护、独立心情及完整短句声音；第二组9次走原QQ生成器、签名虚构入站和隔离传输，普通聊天无逐句确认，批准后清空当前话题仍能召回；第三组3次确认联系人只能取得本人已批条目，主人私密金丝雀未进入模型请求。输入均为隔离虚构资料，正式记忆未改，真实QQ发送为0。用量保留于私有实验账本，不混入正式日常分布。

另从第200轮冻结源码载入旧响应器，对相同两次虚构候选事件作受控适配器比较：原流程2次确认附注，新流程0次；这是机制对照，不是自然使用频率或主观体验评分。隔离浏览器已核对列表、完整预览、确认和保存结果，截图仅含虚构样本；隔离服务已停止，不占用主聊天页面。

实际生成样例仍有无请求建议，因此不签“整体像伙伴”的自然度。原random、篇幅选项、语音开关及人物文件保持；旧显式指令迁移、真实跨夜/三天到期、阈值与长期处理负担继续待验。
