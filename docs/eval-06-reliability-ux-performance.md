# 06｜数据恢复、安全、前端体验与性能

所有破坏性场景只操作副本。报告写入 `evaluation_results/06-reliability-ux-performance.md`，原始脱敏数据放 `evaluation_results/artifacts/`。

## 数据与安全

- 列出聊天、记忆、项目、目标、打卡、情绪、附件、音频、设置、Cookie、密钥的存储位置，并标注唯一来源/导出/缓存/备份。
- 检查 localStorage、默认配置、日志、Git、前端源码是否含敏感信息；只报告位置和类别，不输出值。
- 两请求同时编辑同一数据；模拟保存时进程终止、磁盘不可写；检查 JSON 原子替换、SQLite 事务和重试幂等。
- 在副本恢复记忆、项目、打卡、聊天，核对数量、ID、关联、墓碑和索引。
- 检查备份是否无限增长；验证路径穿越、CORS、错误泄露、外部请求超时/大小/目标限制。
- 若服务能从非本机访问，检查敏感管理 API 的认证或访问限制。

## 前端体验

测试 1920×1080、1366×768、390×844，以及 125%/150% 缩放。完成：首次配置聊天、新建项目、保存记忆、新增目标/check-in、联网识别来源、上传图片、隐藏 3D、从错误配置恢复。

记录每项完成状态、步骤数、困惑点、截图。检查导航/占位入口、危险操作确认、加载/空/错/重试状态、键盘与焦点、对比度、遮挡、长内容、刷新恢复和控制台异常。列出最影响使用的 10 个问题，按影响排序。

## 性能与持续运行

- 记录冷/热启动、首页、首 token、完整回答、空闲 CPU/内存、本地模型加载/卸载内存。
- 测 1/2/4 并发聊天，确认锁等待可解释且零串会话；断连后资源能释放。
- 用 100/1,000/10,000 条合成记忆测写入、迁移、FTS、混合召回、重建；每组至少 30 查询，报告 P50/P95 和存储占用。
- 加载 100/1,000 条消息；连续 50 轮 mock/低成本聊天；条件允许持续运行 2 小时，每 15 分钟采内存、错误数和请求数。

必须写明机器、模型、数据规模和方法；模型推理速度与应用开销分开。给出建议容量区间，不武断声称硬上限。
