- 明确“同一个主人”“共用长期记忆”“接续同一话题”是三件独立事情。
- 将已验证 QQ 身份与网页的用户/会话范围绑定，提供可撤销的接续设置与上下文来源说明。
- 支持明确接续指定网页会话、查看接续来源、创建独立 QQ 话题和停止接续。
- 采用有界近期摘要或经过授权的上下文选择，不拼接所有网页历史。
- 摘要携带来源会话、时间、消息范围、版本、私人属性及生成状态；能处理过期、失败和并发切换。

### 如何实施

1. 复用 QQ 已验证主人 ID；有新增身份绑定时在网页确认，不能凭昵称或聊天中的身份声明绑定。
2. 建立会话关联表，与长期记忆表分开；默认不开启自动历史合并。
3. 从选定会话提取有界上下文，跨端只读接续，不改变网页当前会话指针。
4. 明确 `/reset` 的隔断水位：清当前 QQ 上下文后，旧摘要不能把它自动重新导入。
5. 在共享记忆关闭、绑定解除、会话权限撤销时使派生摘要立即不可读取。

### 防冲突与回退

- 群聊、陌生联系人和临时聊天不得接入主人的网页历史。
- 摘要是有来源的历史数据，不升级为系统指令或用户已确认长期事实。
- 关闭新功能后仍使用原独立 QQ 会话；关联记录保留但不参与提示词。
- Gate：`C05-*`，跨身份、临时聊天、重置与撤销测试通过。

## 8. QQ-06：记忆解释、浏览、修改与删除

### 需要交付

- 在 QQ 查看本次召回使用的记忆及来源，并说明因预算、无匹配或权限未使用的情况。
- 支持搜索与分页浏览已经保存的记忆；保留现有“待确认候选”列表，两者不能混为同一列表。
- 支持查看详情、纠正内容、确认候选、忽略候选和处理冲突；不能把“模型说已修改”作为成功证据。
- 删除、恢复、跨范围批量操作使用明确对象、版本和用户确认；由服务端权限及现有记忆控制服务执行。
- 区分删除长期记忆、清理聊天记录与不再使用某条信息，并明确各自覆盖范围。
- QQ 与网页共用版本、删除标记、候选状态、权限和检索规则。

### 如何实施

1. 在现有记忆控制服务前增加 QQ 命令适配，不独立实现另一套 CRUD 或迁移数据库。
2. 用可分页的短引用展示条目，原始 ID 可供管理但不能充当权限证明。
3. 修改、删除、确认均做版本检查；确认令牌绑定当前身份、操作、对象版本和过期时间。
4. 编辑、删除或禁止使用后，失效对应的检索缓存和派生摘要；保留来源审计和防复活标记。
5. 普通记忆删除不暗中删除原始聊天。若要求“不再使用”，另有覆盖历史派生内容的屏蔽规则，并解释可清理的来源。

### 防冲突与回退

- 关闭保存开关后，普通对话、命令、候选确认、工具及摘要都不能绕过只读限制。
- 不因增大预算重新引入被隔离、删除、失效或超出项目范围的条目。
- 回退适配器不回滚用户已确认的记忆修改；数据服务仍按网页端规则管理。
- Gate：`C06-*`，网页互改、只读、防复活、来源和写入回执测试通过。

## 9. QQ-07：引用、多人群聊与群公共记忆

### 需要交付

- 理解来自当前授权群的引用消息，识别发言人和有限的多人接力语境。
- 群上下文按群和话题独立管理，保留旧的按发言人隔离模式作为默认及回退。
- 可选群公共记忆：项目约定、会议结论等，只进入该群命名空间。
- 明确主人、经验证的群管理员、普通成员的权限表，提供群级开关、保留时长与撤销入口。
- 完善好友申请审核、联系人允许列表与入群审核的界面区分，不自动接受陌生人。
- 默认仍需结构化 @；引用唤醒等新触发方式须单独开启。

### 如何实施

1. 先解析 QQ-03 的引用关系，再通过可信消息读取入口补齐当前群内可访问的原文。
2. 添加独立群公共范围与有界上下文；不复用主人私聊 session 或私人跨端摘要。
3. 群管理员身份通过协议接口核验，不信任用户文本中的“我是群主”。
4. 群记忆写入先采用明确保存/确认，自动采集需独立开启、可见来源和撤销规则。
5. 手动 block 的群必须持续优先于自动入群、首次 @授权及新话题识别。

### 防冲突与回退

- 即使主人在群里请求私人记忆，也不能读取私聊或网页个人上下文。
- A 群引用、转发或猜测 B 群 ID，不能读取 B 群历史及公共记忆。
- 关闭群公共模式后回到旧回复规则；不把群记忆迁移回个人库。
- Gate：`C07-*`，群/人/话题交叉隔离及旧邀请规则测试通过。

## 10. QQ-08：图片、语音、文件及媒体回复

### 需要交付

- 有类型的图片输入：识图、OCR，支持文字与图片共同提问；模型不支持时准确提示。
- 语音转文字：保留识别文本来源，识别失败时允许重发或改用文字。
- 可选语音回复：复用网页已有语音能力，失败时降级文字，防止机器人消息触发自身循环。
- 文件读取首批覆盖有界 TXT、PDF、DOCX；表格和其他格式按现有可靠解析器逐种验收。
- 复用 QQ-03 的长结果，支持代码/报告等附件交付；视频和压缩包不以“文件支持”名义自动启用。
- 统一设置、额度、最大体积、页数/时长、超时、缓存及清理。具体限制作为可测试的服务端参数记录。

### 如何实施

1. 复用现有网页附件、模型路由和语音服务；QQ 层负责协议内容段与附件引用适配。
2. 将接收附件、图片理解、ASR、TTS、文件读取、附件发送分别设开关，逐项开放而不整包启用。
3. 为协议附件建立固定 API/受控缓存解析器；不直接信任消息提供的本地文件路径或任意 URL。
4. 校验大小、真实类型、下载目标、存储目录和超时；文档内容作为外部不可信数据，不能执行宏、脚本或其中的命令。
5. 媒体阶段接入 QQ-04 取消屏障，接入 QQ-05/QQ-07 来源范围，提取文本须经 QQ-06 规则才能成为记忆。
6. 每种类型按“纯文字不回退 → 能处理 → 可取消 → 不支持可解释 → 故障降级”逐步验收。

### 防冲突与回退

- 不把整份文件、音频原始内容或 base64 当作默认永久记忆；缓存与长期记忆生命周期分开。
- 群附件不能借识图、OCR 或识别文本突破私人记忆隔离。
- 附件失败时保留用户文字部分；关闭媒体能力后文本接入继续可用。
- Gate：`C08-*`，每种格式的真实样本及全部前序回归通过。

## 12. 累计发布、回退和完成定义

每项任务按以下顺序交付：接口与失败用例 → 兼容实现 → 本任务自动测试 → 全部核心基线 → 前序阶段回归 → 隔离真实验证 → 小范围开启 → 验收记录。

- 默认发布对象为测试主人私聊；涉及群时使用专用测试群，再决定扩大范围。
- 真实功能依赖未配置时标记 `BLOCKED`，不能用模拟测试覆盖“真实可用”这一结论。
- 任一权限泄漏、重复发送、配置丢失、记忆意外修改或网页基础聊天退化，立即停止推进。
- 回退顺序：停止新接入/相关任务 → 对账已提交副作用 → 关闭新开关 → 回退兼容代码 → 验证旧路径。不能先恢复旧库覆盖新写入的数据。
- 数据迁移优先增量建表/字段；破坏性变更推迟到所有读写端升级后，且需单独可恢复方案。
- 每阶段保留停用新功能后的旧文字通路。新功能失败应按约定降级，不能假装完整成功。
- G9 必须有完整验收记录、遗留限制、实际生效配置、恢复演练和累计回归结果；未验收项保持未完成。

计划中的门禁不能仅凭“测试总数变多”判定通过。必须同时核对基线用例是否仍存在、是否被 skip/xfail、断言是否被削弱，以及真实场景证据是否齐全。
