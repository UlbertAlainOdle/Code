# Memory 3.0 升级制作方案

## 目标

在不依赖增大聊天模型参数的前提下，把现有长期记忆改造成可扩展、可验证、可配置的分层记忆系统。升级必须保留现有 `knowledge.json`，自动补齐新字段，不删除原始记忆，并允许随时关闭新召回逻辑。

DeepSeek 官方 API 当前 V4 模型上下文为 1,000,000 token。系统以此作为 API 模式的默认上下文容量，但不会把大上下文等同于无限记忆：每轮仍使用独立的记忆 token 预算，减少成本、噪声和长上下文位置偏差。

## 分层模型

1. `core`：每轮可优先加入的短小稳定事实，如称呼、身份、长期交流偏好和边界。
2. `semantic`：需要通过查询召回的长期事实、偏好、目标、关系和项目决策。
3. `episodic`：会话摘要、阶段事件、情绪事件和时间相关记录。
4. `archive`：被压缩、过期或手动归档的原始记录；默认不参与普通召回，但保留证据和恢复能力。

排序顺序固定为 `core → semantic → episodic`。层内再按照查询相关性、项目匹配、重要性、置信度、时效性和访问情况排序。锁定和星标只影响分数，不再自动把整段会话摘要变成永久核心上下文。

## 可配置项

- API 上下文 token 数与本地上下文 token 数。
- 每轮记忆 token 预算、预算占上下文比例、单条记忆 token 上限。
- 核心层最多注入条数、相关记忆条数、初筛候选池大小。
- 活跃记忆软上限、归档记忆软上限和检索阈值。
- 自动压缩开关、压缩年龄、最小分组数、每组最大条数、摘要长度。
- 是否包含元数据、是否启用本地哈希召回和自动记忆建议。
- 语义向量开关、提供方、本地模型、设备、批大小、候选数、最低相似度和单次增量索引上限。
- 兼容 embedding 服务的 URL、模型名、API 密钥环境变量名和超时时间；密钥本身不写入设置文件。

软上限只用于状态提醒和触发非破坏性压缩，不会自动删除记忆。

## 实施阶段

### 阶段 A：修复召回与上下文预算

- 为旧记忆自动推断 `memory_layer` 和 `memory_kind`。
- 将核心层与普通锁定/重要记忆分开。
- 使用统一的混合排序分数，避免来源等级形成不可跨越的分数带。
- 按 token 预算组装提示词，避免固定 1200 字符截断和条数放大造成溢出。
- 暴露记忆容量、层级数量和预算状态接口。

### 阶段 B：安全压缩与缓存优化

- 压缩只在相同项目、层级、类别和时间段内进行。
- 每个摘要记录 `compressed_from`，原记录转入 `archive`，不删除。
- 摘要长度和每组数量受设置限制，禁止把全部历史合并成一个巨大条目。
- 访问计数延迟批量写入；只在记忆正文变化时清空向量缓存。

### 阶段 C：SQLite 与混合检索底座

- 将 JSON 作为兼容导出格式，主存储迁移到 SQLite。
- 使用 SQLite FTS5 提供 BM25 关键词检索。
- 增加可插拔多语言 embedding 和近似向量索引。
- 初筛后只对小候选集进行精排与去重。
- 迁移前强制备份，并提供 JSON 回退和一致性校验。

### 阶段 D：评测与容量标定

- 建立固定查询/正确记忆数据集。
- 测量 Recall@K、Precision@K、MRR、冲突率、无关注入率、token 成本和 P95 延迟。
- 在 100、500、1,000、5,000、10,000 条干扰记忆下重复评测。
- UI 显示当前容量状态和最近一次评测结果。

## 本次首轮交付范围

本轮优先完成阶段 A，并完成阶段 B 的安全压缩和缓存写入优化。SQLite、真正的 embedding、近似向量索引和完整评测数据集保留为后续独立阶段，避免在已有大量工作区改动的情况下进行一次性高风险迁移。

## 第二轮实施状态

已完成阶段 C 的本地存储与初筛部分：

- 新增 `memory3.sqlite3`，以原记忆 ID 保存完整 JSON payload 和结构化索引字段。
- 首次迁移前自动生成 `knowledge.pre-sqlite-migration.*.json` 备份。
- `knowledge.json` 继续作为完整兼容导出和故障恢复来源，不会在迁移后删除。
- JSON 写入成功后同步 SQLite；数据库独有而 JSON 缺失的非删除记录会在启动时恢复到 JSON。
- 显式删除使用 SQLite 墓碑，避免已删除记忆在重启后重新出现。
- 使用 FTS5 trigram 初筛中文与英文候选；SQLite/FTS 不可用时自动退回原 JSON 全扫描。
- 核心层不经过 FTS，始终按核心层预算参与；FTS 候选再经过 Memory 3.0 分层相关性精排。
- 设置页显示数据库完整性、记录数、索引数和 tokenizer，并提供不修改 JSON 的索引重建按钮。

## 第三轮实施状态

已完成可插拔多语言语义检索：

- 支持本地 `sentence-transformers` 和独立 OpenAI-compatible embedding 服务；默认本地模型为 `BAAI/bge-m3`，但功能默认关闭，也不会自动下载大型模型。
- DeepSeek 聊天 API 继续只负责对话和压缩。实现没有假定 DeepSeek 官方存在 embedding endpoint；远程向量必须显式配置为独立服务。
- 向量单独保存在 SQLite 的 `memory_embeddings` 表，近似检索桶保存在 `embedding_lsh` 表；构建或重建向量不会修改、删除或覆盖 `knowledge.json`。
- 向量以“提供方 + 模型 + 内容哈希”识别。没有变化的记忆不会重复计算，正文变化后只重建对应条目。
- 查询时合并 FTS 关键词候选和向量候选，再经过原有分层、项目、重要性、置信度和时间规则精排；核心层仍单独保底。
- 向量依赖缺失、模型加载失败、远程服务失败或索引尚未建立时，自动退回 FTS/JSON 检索，不影响聊天启动。
- 设置页可查看已索引、缺失和过期数量，并可选择增量构建或强制重建。

当前环境未安装 `sentence-transformers`，因此只验证了完整的提供方接口、增量索引、融合排序和故障回退，没有在用户机器上自动下载约数 GB 的 BGE-M3 权重。若启用本地方案，需要先安装 `requirements.txt` 中注明的可选依赖；若使用远程方案，密钥通过配置的环境变量注入。

### 当前容量判断

- 每轮真正送给 DeepSeek 的内容仍受“记忆 token 预算”限制；存储 10,000 条记忆并不代表把 10,000 条全部放进一次请求。
- FTS 和向量索引把全库缩小为候选集，随后只注入按层级排序且能装入预算的少量记忆，所以容量上限主要由本地磁盘、索引构建时间和检索延迟决定，而不是聊天模型参数量。
- 按 BGE-M3 的 1024 维规格进行 10,000 条合成向量测试时，向量写入约 3.7 秒，单次检索约 0.37 秒，目标条目排第 1；这只是结构性能基准，不包含模型推理时间，也不等同于真实语义召回质量。
- 在形成真实评测集之前，建议把 10,000 条活跃记忆作为当前的“需监控区间”，而不是硬上限。更大规模应继续做阶段 D 的 Recall@K 与 P95 标定，必要时把当前内置 LSH 换成 HNSW/专用向量库。

## 兼容和验收条件

- 现有 API 路由和前端记忆管理继续可用。
- 现有 `knowledge.json` 中的内容、ID、锁定、星标和来源不丢失。
- 普通会话摘要不再仅因锁定或星标而永久占据核心层。
- 项目记忆不会与全局记忆跨项目压缩。
- 构建的记忆提示词不超过配置预算。
- 关闭 Memory 3.0 分层开关后可以回到兼容召回模式。

## 第四轮：管理界面与 Obsidian Learning Map

- `Life Quests Summary` 使用固定 `managed_slot=life_quests:summary`，并强制为 `core / goal_summary / locked`。普通更新和删除接口不能改写其正文，只能由 Life Quests 系统同步。
- Memories 页面显示 Core、Semantic、Episodic、Archive 四层的用途和数量，支持层级筛选、分组展示、颜色边框和类型标签；整体视觉已改为与主界面一致的深色面板。
- 原 `assistant-role-learning-summary` ID 保留为唯一的 Obsidian 宽泛地图，只记录领域、数量与少量代表标题，不再为普通笔记自动生成长期记忆。
- 先前实验性生成的 `knowledge_area` 与 `knowledge_note` 自动拆分记录不会物理删除；升级时转入 Archive，精选记忆保持不变。
- Assistant 页面提供 Obsidian 文件浏览器。选中 Markdown 笔记后可以标记整篇或某个标题章节为重要，并由模型读取所选全文生成一条独立记忆。
- 简单提取只保留核心主题、结论和不可缺少的概念；复杂提取保留结构、机制、关系、限定条件和结论。简单模式使用快速记忆模型，复杂模式使用强记忆模型。
- 每个精选记忆使用稳定的“文件 + 章节”ID；同一范围再次提取会更新原记录。移除操作只归档，不物理删除。
- 文件夹仍可保存人工路径说明，但不会因此把文件夹中的所有笔记自动提升为长期记忆。

## 第五轮：长度边界与精选知识

- 为生成型记忆增加按类型长度上限：Core 1,200 字符、Semantic 2,400 字符、Episodic 3,600 字符、简单笔记提取 1,200 字符、复杂笔记提取 3,600 字符；均可在设置页修改。
- 上限只约束新生成或重新生成的正文。既有记忆不会被批量截断，避免迁移时丢失信息。
- 容量状态接口会按层统计既有活跃记忆中超过当前建议上限的数量，便于后续选择性重写；Archive 不参与该告警。
- 模型提示中会提前给出硬上限，保存时再做自然句尾裁切作为兜底，并记录 `content_truncated` 与 `original_generated_chars`。
- 最长读取 300,000 字符的单篇 Markdown。DeepSeek API 模式可处理大范围；本地模式超过 24,000 字符时要求改选章节或切换 API，避免静默溢出本地上下文。
- 宽泛 Learning Map 与精选笔记形成两级结构：地图负责知道“有哪些领域”，精选记忆负责保存“真正值得长期记住的内容”。普通、不重要笔记只留在 Obsidian，不占长期记忆库。

## 第六轮：删除持久性与选择性对话归档

- 长期记忆正文以 `knowledge.json` 为兼容主副本，并同步到 `memory3.sqlite3`；浏览器本地存储只记录界面状态，不保存记忆正文。
- 新增 `memory_deletions.json` 文件删除账本。删除时先持久化账本，再更新 JSON 和 SQLite 墓碑；即使 JSON 损坏后从旧备份恢复，已删除 ID 也会被过滤，避免记忆复活。
- 启动时会把已有 SQLite 墓碑合并进文件删除账本，并再次对 JSON、SQLite 两侧应用删除集合。
- Archive 层不等同于不可删除。普通未锁定归档可永久删除；本次退役的 Obsidian 自动拆分 managed 归档也允许删除。仍被系统功能拥有的 active managed 记录和锁定记录继续受保护。
- 当前对话和历史对话执行 Archive 前，都会自动识别已完成的 Doctor/Saya 问答对并显示勾选列表；默认全选，支持全选、清空和逐条取消。
- 只有选中的问答会进入总结提示，系统消息和未完成的单边提问不会进入候选列表；生成的摘要仍受 Episodic 长度上限约束，并记录选中的问答 ID 和数量。

### 主要记忆属性

- `memory_layer`：`core / semantic / episodic / archive`，控制召回阶段和提示词顺序。
- `memory_kind`：记忆的结构类型，例如 `profile`、`fact`、`summary`、`goal_summary`、`knowledge_index`、`knowledge_extract_simple`、`knowledge_extract_complex`。
- `managed_slot`：由具体功能拥有的固定槽位；存在时普通界面不可改写或删除。
- `parent_memory_id`：父记忆 ID，用于压缩来源和“Learning Map → 精选知识”层级。
- `project_id / project_scoped`：限定项目范围，防止跨项目召回和压缩。
- `confidence / importance_score`：置信度和重要性，参与层内排序。
- `is_locked / is_important`：保护和人工加权；锁定不再自动等于 Core。
- `compressed_from / archived_from_layer`：记录压缩来源及归档前层级，支持追溯。
- `supersedes / conflicts_with / superseded_by`：更新与冲突关系。
- `access_count / last_accessed`：延迟批量更新的使用信息。
- `source / source_detail / evidence`：来源、细节和证据。
- `note_ref / chapter_ref / extraction_mode`：精选 Obsidian 记忆的文件、章节与提取方式。
- `content_truncated / original_generated_chars`：生成内容是否触发兜底裁切及模型原始输出长度。
