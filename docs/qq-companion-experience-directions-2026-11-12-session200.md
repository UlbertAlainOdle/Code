# QQ 陪伴体验：表达、操作台与分层记忆探索

日期2026-11-12，America/New_York。用户在R6日常试用中明确要求立即处理内部标签泄漏和移除QQ小表情；另提出三个探索方向。本文件是现状核对与建议，不是新采集策略已经启用。用户补充选择：先分析现有日记忆机制，再给保留建议。

## 一、语音与剩余视觉表达

本机保存的表达模式为random，语音输出与短句语音已开，篇幅引导单独关闭；这些设置保持。15张收藏均已指定且有语义说明，大表情候选并不为空。官方大表情目录与本次移除的普通小表情发送通道分别处理，不删除已有收藏或QQ素材。

保留的24小时指标初次读取有26条样本，其中24条没有附加表达、2条语音；原因包括16次random_none、2次JSON解析失败、1次锚点失败、1次选择超时和4次操作说明等附注抑制。后续读取增加了样本。多数旧指标已无法关联原投递行，混有大量验收消息，不能把这组数当作用户自然聊天的触发率。

已核对的机制：

- random只在模型给出的有效候选中抽取，可以包含none；没有每类固定比例。auto也允许只说文字。
- 收藏需匹配指定语义；颜文字需有唯一、合法的原文锚点。失败时不换另一种表情，也不追加通用笑脸。
- 短句语音已能从较长正文选一句完整原话。超长正文、代码、链接、附注、无有效语音锚点、忙碌或权限变化，仍可能使声音不发送。大表情与语音互斥，颜文字可与语音共存。
- 表达选择目前借普通临时角色生成链，未进入已有的专用JSON任务入口。这是格式干扰的候选原因；两次解析失败的独立原始输出没有完整保留，不能据此断言它们的唯一原因。

建议先按问候、亲近、轻松讨论、安慰、严肃说明、明确要声音和明确拒声音等场景做同条件比较，区分“确实不合适”和“选择器出错”。先验证专用结构化选择及有效短句选择，再决定调整表达倾向。保持用户拒绝、来源、字数、时长、互斥、冷却及不明投递不重发；不以硬凑比例、无条件朗读或出错换类制造活跃。

## 二、记忆操作台与群事件自理

现有网页已有长期记忆与候选列表、版本/权限管理及保存/更正/删除服务。QQ操作还有绑定原会话的预览、确认、结果查询和恢复账本。当前普通答复发现候选时会追加询问，贡献了用户感受到的打断。仅隐藏文字不会减少候选数量，也不能代替真实的确认和写入状态。

建议在现有本机管理入口上增加统一操作台：

| 区域 | 用户看到的内容 |
| --- | --- |
| 近期印象 | 日摘要、保留期限和最近变化，默认无需逐条批准 |
| 待决定的重要内容 | 完整正文、已有相近条目、来源说明；保留、暂不保存或更正 |
| 最近操作 | 已保存、未保存、失败或结果待核对；编号和版本放在详情 |
| 操作输入 | 自然语言或已有受限命令，调用相同的已登记操作服务 |

普通聊天不追加候选清单或【操作回执】气泡。用户主动询问保存结果，或失败确实影响当前明确请求时，QQ用一句自然且真实的话说明。不能在尚未提交时口头声称记住了，也不能只消掉失败提示。

操作台需要绑定原QQ作者、作用域、原来源和操作身份，沿用CAS、预览与幂等账本。原网页入口不允许伪装QQ会话，这个限制保留。队列项可以等待用户回来，确认时重新读取当前版本；不能靠永久保留旧确认码绕过重启作废和来源失效。相同候选按对象与内容版本归为一项，避免每轮重复询问。

群事件的普通收录与接续本来即可自动进行，主人的QQ在线与否不应成为每条更新的人工审批门槛。仍要区分成员意见、本人承诺和已确定的共同决定；共同决定及管理操作沿原协调人/作者权限执行。自行整理不代表自行宣布成员同意、替人完成事项或主动扩开整群采集。当前群仅@等准入范围保持，超出该范围的方案需另行明确。

### 群聊现在是否使用记忆

群公共语境、群事实和逐条授权的个人长期记忆有独立实现。当前本机没有群策略条目，因此该层的群记忆开关处于默认关闭；统一群事件卡是另一条已实现的来源路径。群事件不等于把主人私聊记忆灌进群里。以后开启群记忆时，也只能使用本群材料和明确授权、版本仍有效的个人条目，保持作者与可见范围。

## 三、现有日记忆核对

现有`DayStateManager`主要保存联系/对话次数、网页加载和后端启动次数、任务快照、待续任务编号及天气。D0至D3权重环用于读取近期状态。

它与设想中的日对话摘要有几个实质差异：

1. 以日期作为主键，没有按QQ账号、人物、群和可见范围隔离的聊天正文，不能直接放进所有人的对话事实。
2. 正常聊天和启动路径更新计数，没有调用已有rollover清理入口。核对时有20行状态，跨度超过四天；四日读取窗口不能视为四日后已经物理清理。
3. 默认日期路径使用主机日期，timezone字段本身没有解决按QQ保存时区切日。新的聊天日摘要必须显式计算会话日期并测试午夜边界。

本轮没有清除旧日状态、回填聊天或改变其保留策略。新设计应复用已有来源、版本、作用域、过期和遗忘能力，避免再造一套无法对账的永久档案。

## 四、双门槛建议

建议先以七天滑动窗口试用日对话摘要，覆盖一周内自然接续；这是可调的初始建议，不是已保存的新设置。按机器人、对象/群、可见范围和当地日期分开，每日最多一个有界正文，持续更新。正文与来源引用都要有容量、有效期及真正的清理执行；不能靠把多条来源包成一个摘要绕过原32来源或卡片上限。

| 条件 | 建议行为 |
| --- | --- |
| 不到低价值门槛 | 保留原允许的近期聊天，不另建记忆条目 |
| 达到低门槛 | 更新当天对应对象的短期摘要，静默处理，无逐句确认 |
| 主人内容达到高门槛 | 可继续用于近期接续；重要候选进入操作台，确认后才单独写长期记忆 |
| 其他人私聊达到低门槛 | 仅对应人的隔离日摘要，不进入主人的重要记忆确认队列 |
| 已有长期条目出现新版本 | 优先提出更新原条目，避免每日重复新增同一偏好 |

两个门槛衡量保留价值，不能把“低门槛”理解成降低来源或事实要求。问题仍是问题，猜想仍是猜想，转述保留作者；助手解释不变成用户经历。明确保存请求沿原显式保存合同处理，不应因评分低被丢掉；明确不记、停用和遗忘优先于自动摘要。

高门槛考虑长期复用价值、明确稳定偏好、重要承诺及已有条目的更正。强烈情绪、文字较长或模型自报高置信都不能单独证明需要永久记忆。分值需由实际样例校准，暂不敲定数字阈值或自动保存比例。

同一天更新不能简单用最后一句覆盖前文：保留仍有效的条件、否定、作者、适用时间和矛盾。相同重要候选去重，用户未确认或选择暂不长期保存时不能自动升格；“不存长期”和“不再使用这件事”的处理需在界面中清楚区分。日摘要的历史版本也必须有界，不能在每日正文到期后把原内容永久留在版本或审计副本里。

## 后续实施与验收顺序建议

先验证表达选择的技术失败和短句语音漏触发，保持现有模式和权限。操作台与双门槛应联动设计，避免先隐藏确认后仍大量累积候选。日摘要从关闭状态的独立样例开始，验证跨账号/群隔离、切日、过期、更新、遗忘传播、重要队列去重及原写入结果恢复；明确新范围后再进入有限日常试用。阈值和期限需通过真实体验调整，不能只凭条目数变少宣称陪伴体验改善。
