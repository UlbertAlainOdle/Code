# 第51轮：桌面QQ气泡顺序调查与现行语音规则

用户确认问题是同一回答内气泡先后颠倒，手机端正常、电脑端异常。本轮按客户端日期2026-11-01记录，核对第50轮311文件指纹全部一致；只读调查，无业务源码/运行配置变更、无重启、无QQ代发、模型/TTS合成或付费探测，未重复无差异的218项自动检查。

## 顺序证据和结论限度

当前chat/natural模式，每批最多3条、目标240字符、首条引用问题。qq_delivery.lookup按seq排序，send_batch逐段await send_part，取得有效回执并落库后才进入下一段；没有在同一份回答里并发发送所有气泡。首条使用问题引用，后续保留普通气泡。

从数据库取最近8份已发送至少2段的final回答（7份群聊、1份私聊），按持久段序读取22个真实QQ回执，get_msg均匹配机器人/消息ID。22条时间在各回答内均不倒退，**8份真实real_seq全部严格递增**。7份各存在1对同秒气泡，总计7对。

特别核对固定安装的NapCat源码：get_msg中的message_seq/real_id被赋为message_id，不能按其数值判断真实先后；原生msgSeq另在real_seq中返回。本轮最终结论只使用real_seq。初始只读检查程序曾比较message_seq，离线纠正到real_seq后保存结果，不把随机协议ID的下降当作服务端逆序。

对这8份样本，没有发现应用或QQ已记录消息序号的逆序。结合用户手机正常、电脑异常，证据更支持电脑端同步/展示排序差异；尚未定位电脑QQ的具体缺陷，也没有直接看到用户所指批次的桌面显示，不能称QQ官方已确认bug。同秒快速发送是可疑兼容条件，尚未证明它就是根因或添加延时一定有效；本轮未改变气泡策略、追加编号、重复发送旧内容或强制重启QQ。

后续可切换到其他会话再重新打开原聊天，核对同一批历史气泡是否恢复；保持手机对照。若需要后续节流实验，应只改变气泡间隔并分别记录两端结果，不改变正文顺序或倒填通过，不能使用重发历史回复来制造对照。若已能稳定复现，再根据用户实际顺序定位具体段落与真实real_seq。

## 现行语音触发（本轮重读实际配置及源码）

媒体voice_reply_enabled=true；TTS enabled=true、qwen_local、clone、vllm_omni，mood_prosody=true。语音开关不隐含附件读取或私人记忆权限。

1. 授权私聊/群聊的新生成final回答走chat投递，全部文字分段均已确认sent后，才尝试额外发送一条本地原生QQ语音。同一结果仅尝试一次，不逐气泡附语音，不因续读重合成。
2. 整份canonical回复1～120字符（不是每气泡120）；拒绝包含代码围栏、HTTP链接、CQ标记、管道表格行或“已保存长期记忆”回执的内容。长回答、控制回执、自然确认执行回执、legacy、继续说/续读不触发。
3. 当前输入含“不要/不用/无需/别……语音/朗读”或“只要/只用/只发文字”会跳过。当前是符合条件的短回答自动附语音，并非仅在用户说“用语音回答”时触发；请求语音也不能绕过长度和其他门槛。
4. 复用现有声线与本地TTS、会话心情韵律；合成等待最多45秒，最终音频最多30秒、单声道PCM16、2MiB。缓存最多32个/32MiB、保留300秒并定期清理。语音服务忙、失败、超时、取消、撤权、声线或策略变更时保留已发文字并停止/跳过语音，不为此再生成一份回答；发送结果不明不自动重试。

本轮语音表只读统计仅有历史expired记录，未进行发音或QQ音频验收，不能据此签收主观听感。原第50轮引用/Mood及第49轮群文件最终真人反馈依然待验，图片双端/私聊文件既有用户确认保持。当前仍第8阶段，ASR/附件输出未实现。
