## 已核实的现状

`qq_delivery.semantic_parts`先以`target`取字符长度，仅当剩余文字超过该长度时寻找换行/句末。因此默认`bubble_chars=240`下，120～230字即使有两三个段落也仍是一条。这是现有规则的行为缺口，不是用户设置丢失。`send_batch`给所有多段结果加`[当前/总数]`，普通两条聊天也会呈现分页感。表达提示要求短句和80～200字，但没有要求在不同意思之间使用自然段。

## 推荐：自然段优先，长度兜底

新增可选的“自然分消息”策略，与原“按长度分段”策略并存；不改人物设定，保留原240字设置作为该策略下的长度兜底。以下范围是待实测调节的软目标，不是当前上线功能或逐字硬切标准。

1. 短问候/简单完整答复通常一条，例如约60字内；不为了两条而添话、逐句打散或重复称呼。
2. 中等长度有2～3个完整自然段时，优先按段发送，即使合计不到240字。每条通常约40～120字，可适当放宽；约20～30字以下的孤立碎句优先合并。按连续意思分段，不要求每条等长。
3. 一整段约120～240字时，可在完整句末选择1～2个边界，避免一大条；“按意思”由模型的自然段和句界提供线索，规则本身不能保证理解任意语义。没有合理边界就保留一条。
4. QQ表达层仅补充“自然分段、一段一个意思、无需刻意补字”，用普通空行，不新增模型隐藏分隔标签，不让控制标记问题重演。只分配一次生成的完整答案，不逐条重新调用模型/搜索/记忆保存。
5. 仍服从默认每批最多3条；普通中等回复通过合并小段尽量在同一批完整送出。真实长文才使用原续读，不为制造聊天感而频繁要求/continue。
6. 普通两三条短聊天不展示`[1/2]`等分页编号；真正需要续读的长结果保留段序和余量提示。底层结果/段编号、发送回执及发送不明冻结仍保留。
7. 代码块、表格、连续步骤/列表、长链接、引用/原话等使用保守分割规则，短内容整体保留，超出硬限制才切分；已提交记忆回执和失败/未核实提示不得隐藏、重复或挤出首批。控制指令回复不套用碎片化聊天规则。
8. 群聊沿用每批首条引用/@策略，不在每个气泡重复提醒。人格、身份、共享记忆与会话隔离不变。

## 节奏与耗时

第一版建议先优化分句和可见编号，不加随机“假装输入”延迟。现有单消费者中直接sleep会延迟其他会话；若后续希望增加气泡间短间隔，应独立提供可关闭选项，按有界调度/取消/停机预算设计，不能承诺零影响。分消息也不会减少既有Search/Fetch或完整模型生成等待；边生成边发、任务进度/取消仍按QQ-04门禁另做。

## 验收

| 场景 | 期望 |
| --- | --- |
| 20～60字单一意思 | 1条，不强拆/补字 |
| 合计120～220字、2～3完整自然段 | 通常2～3条，未达240也能拆，普通聊天不带分页头 |
| 一段中等长度、多完整句 | 依合理句界拆1～3条；不从句中/组合字符/URL截断 |
| 多个很短段/只有语气词 | 合并碎段，避免刷屏，限额不变 |
| 代码/表格/步骤/引用/链接 | 保留必要上下文与结构，不按空行盲拆 |
| 超长回复与真实保存回执 | 首批条数受限、提交回执可见且仅一次，/continue顺序不变 |
| 发送不明、重启、旧结果/切换策略 | 不重放sent，不跳过unknown，不重排旧缓存，旧格式可恢复 |
| 过滤、来源、群/主人/记忆 | 原协议清理、显式来源、群首批提醒及权限保持 |
| 网页和设置冲突 | 网页回复规则不变，QQ设置两端同源，旧修订拒绝，旧字段安全兼容 |

真实验收分别观察短问候、中等自然回复和一份长结果；无需公开完整聊天。自动化不算真人回复确认。本轮只有评审，未运行测试或重启，沿用第十六轮原有证据而不新增通过计数。
