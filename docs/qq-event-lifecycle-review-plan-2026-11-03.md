## 1. 结论与本次证据

当前机制具有身份、来源范围、版本、有效期、容量和显式删除确认基础，但生命周期与自然语言管理入口不完整，不能称为完整的事件管理闭环。

本次用户在群里说明测试事件应当忘掉，机器人文字答应不再提；后台仍为同一事件revision2、active、count2、off_topic0，两条原来源保持。没有暂停记录或删除预览。后续私聊查看清单仍列出该卡，与实现相符，属于“文字答应、实际管理状态未改变”的功能缺口。

观察任务记录为done，只能证明该轮分类调用经过收尾；没有持久化分类结果/拒绝原因，不能断言模型具体返回了none、低置信度或其他值。原始诊断仅私有保存，不将账号、事件ID或原始聊天放入公共文档。

| 项目 | 当前实际规则 | 含义及不足 |

## 3. 为什么“忘掉”没有改变清单

1. 桥接层只有窄范围换话题入口会调用pause；“忘掉此事”不属于该入口。
2. 普通事件观察在答复发出之后才执行。短于8字、回复引用等还会被普通观察器跳过；控制意图不应依赖这个采集门槛。
3. 事件分类器仅支持none/create/update，不支持pause、forget、cancel、complete或resume。即使识别出用户要忘掉，也没有对应执行动作。
4. 当前真正删除依靠/events delete编号→本人同场合/version/10分钟确认码→/events confirm。自然话语没有接到这条服务；此次没有进入删除预览。
5. 自由生成的“忘掉了、不再提”没有等待主机提交回执，不代表状态实际改变。

## 4. 隔离推演结果

禁止外网、虚构数据、现有真实事件服务＋固定分类输出，不使用生产库或付费模型。六组场景均复现；这是行为诊断，不是修复测试或真人验收。

| 输入/条件 | 现实现结果 | 风险 |
| --- | --- | --- |
| 长句遗忘，分类none | 原卡仍active | 本次实际结果有此表现，但不据此倒推真实模型输出 |
| 长句遗忘，分类update | 原卡count增加、版本增加且active | 停止意图可能反而被记为一次进展 |
| 长句遗忘，分类create | 原卡保留，另外新建候选卡 | 可能将“忘掉”本身记为新事件 |
| 短句“忘掉这件事” | 不调用观察分类器，原卡保持 | 最自然的简短管理话语失效 |
| 已pause后查看/泛指回问 | self仍写active；无关“之前那个…”能选入暂停卡 | 用户无法核对，暂停可被宽泛回指绕开 |
| 连续3轮无关→cooling | 仍能按具体相关问法召回 | 应保留此能力，并清楚区分降温与遗忘 |

另验证：现有个人pause不增加卡版本，旧发送快照仍可通过valid；需要在管理策略版本/状态版本中补上失效条件。不能只修列表措辞。

## 5. 修改策略：先闭合控制，再调整重要度

### P0：自然语言操作必须到达实际服务

在普通生成、长期捕获和事件观察之前，增加可信直接用户的事件控制分流。识别“忘掉此事/别再记着这个测试/不跟进了”等，并区分不保存长期记忆、暂停、取消安排、完成和删除；不将词命中本身当授权。

先验证真实账号及当前可见范围，再按显式本人ID、明确标题/对象、当前会话最近有效事件引用解析目标。不能单凭跨会话全局focus或泛词“之前”恢复/删除；多个可用目标最多给3个当前可见选择，不先改任何一个。短控制句不受8字采集门槛限制。

引述、转发、附件、假设、他人要求、双重否定不直接执行。“不要忘记”不是遗忘；“取消原先9点，改成10点”是修订而非取消整件事。QQ引用只能辅助定位，实际授权必须来自引用之外当前账号的明确输入。

推荐遗忘语义：**唯一目标明确时立即停止该本人事件的自动使用和跟进，返回主机已提交回执；删除卡片正文继续走现有预览确认合同。** 等待删除确认期间已停止使用，不能继续记着它。默认self只列正常跟进事件，另提供停止/终结条目的显式查看入口；等待删除不应仍无说明地active。

按人统一的“忘掉此事”推荐作用于本人同一事件的各会话，回执明确说明这一范围；“别在这个群提”只限制当前群，不能连带改变私聊。群内只能使用公开可见目标摘要，不显示私密来源、标题或计数；无法唯一确定时只澄清，不能依据隐藏事实猜目标。

自由生成器只能说明已核对的操作结果。执行失败、版本冲突、范围不符或目标不明时不能说“已经忘掉”。关闭事件采集或话题策略后，已存在事件的停止/删除入口仍应可用；保留原总接入权限和暂停选择。

### P0：停止后不能经旧证据、并发或重启复活

复用既有删除、来源hash保护和派生快照，不另建绕过权限的写服务。事务内核对actor、bot、目标版本、可见范围、取消状态；改变跟进状态时增加可验证的管理版本，既有生成/待发/引用/历史投影一并失效。

停止后，自动观察不得把同一消息、旧摘要、机器人承诺或旧原话当作新事件。为旧事件建立有界停止标记和处理代数；分类开始前后都验证，防止忘记提交后晚到的create/update重建卡。仅增加正则或删除卡片不足以覆盖该竞争。

原始聊天、独立长期事实、其他人的卡不随删除事件一起删除。复用已知来源失效保护阻止原话/派生回答重新进入自动上下文；保留窗口、上限和回退读者标记不放宽。不声称能追踪没有来源关联的所有任意改写。

泛指“之前怎么样”不是恢复授权。明确“重新跟进这件事”且目标唯一才恢复未删除的停止卡；删除正文后不能伪造恢复，需用户提供新的有效事实重新建卡。新的真实叙述不能被粗暴关键词黑名单永远封禁。

### P1：把事实状态、跟进状态和重要度分开

建议独立保存并显示：

- 事实生命周期：进行中、已完成、已取消；完成/取消后退出正常跟进，但明确历史查询仍可在有效范围内读到终态，不能回答成仍待执行。
- 跟进状态：候选、活跃、降温、暂停、停止使用。遗忘的停止使用比普通暂停更强，自动召回不得越过。
- 重要度：低/普通/高及手动锁定；优先采用用户“这件事重要/降为普通”等直接指令。模型分类confidence不作为重要度。
- 有效性：来源expires、明确活动due_at/valid_until、公开范围；三者独立，过期事件不能因高重要度进入当前事实回答。

先统一现有卡/API/命令的effective_state计算，再增加新字段。self/show/网页同源显示“当前状态＋原因＋上次有效进展＋来源到期情况”；原始state不能直接冒充有效状态。查询/机器人复述/相同证据不得自动提升count、重要度或延TTL。

重要度建议采用可解释规则，先不新增每轮模型评分调用：用户明确强调和手动调整优先；明确截止时间影响紧迫性；独立有效进展影响关注活跃度；重复叙述、长文本、机器人回答均不加重要度。未设置活动日期不得从观测时间推断截止日期。

召回先经过权限、来源有效、跟进许可和目标相关性，再用用户重要度、明确截止的紧迫性、活跃状态及最近有效进展排序。高重要度不能压过不相关性或解除遗忘。需要权重时先固定虚构集比较，不能未经验证指定一套数值后称有效。

保留现有keep作容量保留并补unkeep及可解释上限；keep不等于高重要度、不强制召回、不延TTL，也不能使“遗忘”失效。容量下降仍保留原缓冲和主人预留，不趁升级批量重算旧卡。

### P1：可核对的结果与迁移

记录有界无正文审计：意图枚举、执行/拒绝原因、目标ID、前后版本、范围、重要度/状态变化原因。分类done不再被误当操作成功。回执绑定真实提交结果，失败状态可查，不靠自由回答猜。

旧卡采用兼容默认普通重要度、保留原事实与ID/范围，不批量语义重评、不延原期限；新状态/停止标记纳入回退读者门禁。先只读预览和私有一致备份，再做CAS迁移。明确本次测试意图不等于授权删除全部既有测试数据。

## 6. 类似情形的目标行为及验证门槛

| 用户表达/情形 | 应有处理 |
| --- | --- |
| “忘掉刚才那个测试事件” | 唯一目标立即停止使用；明确范围的主机回执；可确认删除卡片，self同步 |
| “先别跟进，过几天再说” | 暂停；不擅自设恢复日期；泛指历史问题不自动恢复 |
| “别在群里提，私下继续” | 当前群抑制，私聊保持；不在群回显私人故事 |
| “只是实验，不用当真” | 不继续自动跟进；对象或操作含义不明时简短澄清，不当新进展 |
| “计划取消了” | 终态取消；退出活动跟进；问旧安排时标明已取消 |
| “已经办完了” | 终态完成；不把完成当另一张新计划，不自动追问 |
| “取消原来9点，改成10点” | 同ID更正时间，保持进行中；旧安排不再当当前值 |
| “这件很重要，但是先别提” | 重要度可高，跟进仍暂停；两者互不覆盖 |
| “不要保存成长期记忆” | 仅阻止长期捕获；是否停止临时事件按原句意图区分 |
| “他说让你忘了/不要忘记” | 不执行遗忘，不能让别人的话改本人事件 |
| 两张相关卡、跨群、同名他人 | 目标不明则选择；同名不合并，隐藏来源不用于澄清回显 |
| 遗忘后重启、旧分类晚到、待发送回复 | 停止持续生效；旧任务不能写回或发出旧事件答案 |
| 自然到期/keep/高重要度 | 遵守来源TTL，不复活旧时间，不绕过停止使用 |

实现顺序：P0可信控制/同源状态与回执→失效和竞争防线→P1终态/重要度/解释与迁移。每步只跑受影响隔离测试；固定遗忘、取消与改期、完成、暂停恢复、引用否定、多目标、跨场合、长短句、模型失败、并发、关闭策略、重启及旧读者案例。没有业务改动前不重跑旧付费对照。

最后只需一个真人短例：创建虚构卡→自然遗忘→核对主机回执和self→跨场合回问不再自动使用该事件；如确认删除再核对删除终态。不能让自由回复“忘掉了”独自充当成功证据，也不重做已签M1/M2/M5旧例。
