# Saya 与 QQ 后台管理

双击项目根目录 `start_saya_qq.bat`。现在打开的是管理面板，替代第65轮仅打印READY的启动窗口。它会启动或复用当前项目的应用、专用QQ/NapCat，并检查接收状态。

| 操作 | 行为 |
| --- | --- |
| 启动 | 启动或复用，等待应用/接收/NapCat/账号就绪；异常显示原因 |
| 停止全部后台 | 暂停新任务、等待现有任务、卸载语音、停止辅助服务/应用/守护/专用QQ，复查后保留面板 |
| 重启 | 先完成停止和核验，成功才重新启动；停止未确认则不继续启动 |
| 刷新状态 | 查看本项目进程类型、PID、相关端口及归属/检查缺口；平时自动刷新 |
| 记忆操作台 | 直接打开原生子窗口，查看每日稿、重要待批项、更新提案与已保存记忆；无需打开浏览器 |
| 停止并退出 / 右上角关闭 / Alt+F4 | 执行停止并核验，成功才关闭面板；失败保留窗口和原因 |

最小化面板会继续运行。关窗时等待窗口自行退出；若有任务、语音释放或QQ退出仍在进行，窗口会显示操作中。不要用任务管理器强杀面板来代替受控停止。

记忆操作台的关闭按钮只关闭子窗口，不停止服务。今日稿按已保存的 QQ 时区每日00:00结算，日终后在窗口内查看完整正文和用户来源，再选择保留到长期记忆或本次不保存；待批三天过期。其他人的私聊稿也由主人在这里批准，不建立群每日稿。已保存记忆支持查找、翻页、全文查看，以及删除、停止使用和恢复使用；后三项先显示完整预览与影响范围，再点击确认，不需要在QQ复制确认命令。后台重启、切换原QQ话题、版本或权限变化会使旧操作确认失效；结果待核对时不自动重试。

第204轮新增“明确保存与旧候选”页及“已保存记忆→编辑／补充”，工程和隔离原生验证完成；截至该轮交接，正式后台处于手动停服，尚未启动核验，不能当作已上线。下一次按原入口启动后，应先完成该轮部署与保留对账。明确保存请求在QQ只给简短提示，完整选择和确认移到原生操作台；普通每日稿仍沿用上段规则。旧候选可确认保存，也可单独“忽略原候选”；“本次不保存”仅取消本次待办。编辑先显示完整前后正文，确认后更新原编号，不另存为第二条记忆。明确保存沿用原来源的十分钟确认期限，重启后须重新预览；离线清扫与每日任务共用原后台周期。具体范围、未迁移路径及当前启动状态见[第204轮记录](qq-native-save-migration-2026-11-14-session204.md)。

窗口下方支持“查看待确认”“查看今日”“查看最近操作”、`查看 待批编号`，以及原 `/memory list`、`/memory show 编号`、`/memory result 操作编号` 查询。尚未迁移的旧显式保存、候选选择、归档等仍沿用原入口，不能认为所有QQ操作回执都已移出聊天。维护排空期间暂停新的操作台写入，并等待已经提交的写入结束。详细实施和剩余项见[第203轮记录](qq-native-memory-console-2026-11-14-session203.md)。

“已全部停止”要求检查中没有项目受管进程、相关端口占用或核验缺口。面板自身不算后台；停服后保留面板时，它仍是一个前台Python窗口。应用、守护、项目启动外壳、专用QQ/NapCat、语音及Minecraft辅助、WSL语音/GPU工作进程纳入检查。WSL进程依项目随机token核验；历史pid文件会核对实际活进程，不直接当作残留。

仅操作本项目可验证归属的服务，不按QQ/python/node进程名全杀，不终止日常QQ、其他项目或WSL系统服务，也不执行全局`wsl --shutdown`。陌生端口/无法确认的项目进程显示未完成，不伪装为全清理；在其原窗口正常退出再重试。系统的WSL宿主进程可能继续存在，这不等于本项目语音模型仍运行。

原人物、声线、收藏说明、模式、API凭据和启动选择保留，不新增Windows登录自启动或开启NapCat崩溃监督。语音沿用原启动预加载/空闲释放设置，停止时显式卸载，不修改音色或自动下载模型。QQ完整退出后再次启动可能需要手机确认；需确认时面板会提示，不自动操作认证。

脚本入口（需要命令行时）：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/start_saya_qq.ps1 -Action panel
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/start_saya_qq.ps1 -Action start
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/start_saya_qq.ps1 -Action stop
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/start_saya_qq.ps1 -Action restart
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/start_saya_qq.ps1 -Action status
```

CLI status返回JSON；面板/CLI通过工作区操作锁避免并行启停，已有面板时不会再创建第二个控制窗口。不要同时运行旧的网页专用`start_saya.bat`或`start_saya1.bat`竞争8000。异常强杀、断电或其他程序另行启动服务不属于正常关窗保证；重新打开面板检查实际状态。
