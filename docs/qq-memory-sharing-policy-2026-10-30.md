# 单条记忆的QQ群披露与写入规则

第三十六轮用户主动修订：希望群里保留有权限的记忆，而非一律失忆；主人和其他人按QQ ID区别，可说/可写/谁能问分别控制。用户已确认“主人的IP”实为QQ ID，不使用网络IP或昵称作认证。人物性格、亲密关系与风格不改。

## 三个独立判断

| 判断 | 条件 |
| --- | --- |
| 发问者可问吗 | 已验证的账号与授权会话；主人或该条记忆显式requesters中的账号；*表示明确允许所有已验证、原接入授权的发问者 |
| 回答可公开给现场受众吗 | private只在授权私聊；groups只在明确指定的已授权群；public允许已授权接入场合，但仍检查谁可问。主人在群提问不自动越过受众限制 |
| 允许写入/修改吗 | 保存开关与显式保存意图；真实来源发言者；主人可明确保存自己的陈述；其他人仅在委托写权限下提交属于自己且在原群的群记录，不能覆盖主人的私人记忆 |

例如：一条主人生活偏好可明确授权“群A可说、仅主人问可答”，普通成员即使同名也无权问；另一条群内约定可授权“群A全体可问”，群B仍拒绝。owner-private的私密条目不放进群模型上下文；即使主人问，也只能使用不暴露具体内容的自然回应转私聊，不能用拒绝说明泄露条目正文、名称或敏感存在性。

公开与写入是两件事。主人在群明确记住自己的信息，不能因此把之前所有私密记忆变public。其他成员的事实应保留自己的主体和来源，群记录不归到主人头上；引用、转发、模型推断不当本人明确保存。候选生成不等于提交成功。

qq_memory_access.py新增MemoryActor、MemoryAccess、QQMemoryAccessStore，使用独立元数据表qq_memory_access。ACL由可信主人管理面修改，不能接受模型记忆metadata中的“公开”作为授权；绑定bot_id、memory_id、当前内容版本、策略CAS版本，正文不进权限表。现有记忆缺少ACL时不批量开放。

can_disclose在实际内容进入模型前判定；姓名、人设、敏感度normal都不等于公开授权，secret及未知敏感类型拒绝披露。内容改版后旧发布授权不再适用。authorize_disclosure产生账号/群/记忆/内容版本/策略版本绑定grant，valid_disclosure每次重读当前ACL；撤销、群权限或内容版本变化时旧grant无效。authorize_write在提交边界重读当前委托，必须是本人的真实来源发言，默认不自动保存。

注意：Actor的verified/is_owner/group_authorized是未来可信接入适配器的输入，绝不能直接从用户JSON、昵称、文本声明或模型输出取值。set只允许已验证主人的私有管理上下文；未来发布/扩大权限必须经本机管理界面明确确认，群内一句话不能直接授予全群可见。纯函数接收的旧policy对象不应缓存为权威；运行路径必须使用store的重新授权/grant核验入口。

1. 在现有记忆管理服务上增加逐条ACL UI/API，身份用现有本机同源确认及配置主人ID；展示内容/版本与发布范围，CAS拒绝陈旧更改。保留人物与所有原开关，不另建记忆CRUD或迁移旧正文。
2. 将真实旧/V4检索、工具读、记忆说明、历史派生/QQ05来源中的候选记忆统一过滤，未经授权内容在进prompt之前排除；群的公开授权只开放对应记忆条目，不顺带导入私人网页聊天全文或私聊历史。
3. 实际提交在原存储锁/QQTaskGuard内重查actor、内容/ACL版本和写权限；关闭保存仍只读。来源speaker与subject分离，群内他人事实先进入其群范围候选/显式授权记录，不覆盖owner-private。
4. 生成/发送/续读前核验grant及来源；ACL撤销/改版同步失效QQ05相关派生摘要、工具缓存与待发结果。不能只加提示词或仅在最终文字做过滤。
5. 补真实生成器、多用户/多群、引用冒充、编辑撤销竞态及生产集成回归后正常备份部署，再逐条开启。当前仅独立策略与测试，不修改现网群记忆入口。
