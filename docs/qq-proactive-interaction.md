# QQ与网页主动互动使用说明

第73轮，2026-11-01。QQ主人私聊主动互动已实现，网页主动回声已升级。现有人物设定、声线、过滤器和原开关保留。本轮开工时后台已手动停止，因此只交付代码及隔离验证，未启动正式机器人或开启主动消息；下次从原管理面板启动后生效。

## 启用QQ

1. 双击项目根`start_saya_qq.bat`，等管理面板显示接收正常；需要登录时仍由手机确认。
2. 打开`http://127.0.0.1:8000/static/qq-proactive.html`，读取当前设置，明确选择接收主人账号。选择需要的话题来源、时区、免打扰、空闲时间、最小间隔与每日上限，再打开并保存。
3. 也可在配置主人好友私聊发`/proactive on`或`/主动 开启`，默认只用最近私聊话题。`/proactive`查询，`/proactive off`关闭；命令走独立控制通道，不等待普通长任务结束。群和其他账号不能开启或成为首版主动目标。

QQ新增开关默认关闭，网页开关与它独立。默认空闲至少30分钟、两次考虑间隔60分钟、每日最多1次、23～8时免打扰，默认时区America/New_York；按本人位置修改，例如Asia/Shanghai。开始/结束相同表示不设安静时段。每日上限为0表示不主动发送。

“最近私聊话题”限该主人的当前QQ私聊；没有真实私聊历史时不主动联系。项目、日期记忆、日记来源还要求原主人私聊共享权限，并且对应来源被选择，不会自动打开共享。生日/纪念日可作已知话题，本版本不创建精确预约提醒，不能靠一句口头答复假称设好闹钟。

## 启用网页

原主页面Settings里的Companion／主动回声保留原总开关与项目、日期、日记来源，新增最近聊天来源、空闲时间、考虑间隔与时区。开启回声并至少选一个有内容的来源；使用已保存的普通会话。临时聊天、助手模式、隐藏页面、正在生成回复或输入框有未发送草稿时不插入主动消息。当前活跃页面有来源且网页回声开启时优先网页；页面不活跃时QQ后台仍可独立工作。

网页已经改为准备→提交到明确会话→页面展示确认。准备不算发送；确认后才记已展示，刷新可从原聊天历史看到，重复请求不重复保存或计数。切换会话/页面或来源撤销时不把旧话放进新聊天。不再使用旧回声的固定人物话术或失败后模板补发。

## 如何决定

后台每30秒做本地资格检查；网页每5秒更新页面存在状态。没有话题、未达到空闲/间隔、免打扰、正在忙碌、已有待处理消息或已达上限时不调用模型。符合条件后，当前人物模型读取真实时间、距上次交流时长、八维心情与少量授权上下文，在候选话题中决定开口或沉默。模型不会为凑次数强制问候，也不能把候选/旧对话当新权限。

每次只先发一段不超过120字的短话。QQ可选表情/语音继续复用原语义规则：声音可配小表情或颜文字，与大表情互斥。成功主动消息作为机器人真实发言带时间保存，不伪造用户新消息、不自动保存长期记忆、不自动开搜索权限。之后可继续聊或引用它，引用作者仍按真实账号识别。

网页和QQ协调同一接收者的消息记录、所选话题/来源版本与当日计数；同一项目/来源不会两端各发一次。两端都受各自设定的上限约束；发送结果不明不当作成功，也保留不明额度，避免丢失回执后超量发送。没有新的用户交流时不连续追问。断线、重启、过期不会集中补发旧话题。

## 启停与试验

所有工作都在原受管后端里，不新增Windows任务、独立常驻程序或Codex自动任务。关闭原管理面板仍按原规则停止并核验后台；不运行时不发送。

若想快速试用，可临时选最近聊天、空闲1分钟、免打扰开始结束设为相同，保持每日1次；先正常聊一个能后续展开的话题，再安静等待。模型可能选择沉默，不能把每个空闲窗口都预期成定时提醒。使用后恢复常用时段和间隔。网页和QQ分别观察，正式收件与自然程度仍需真实反馈；本轮没有代发生产QQ消息。

自动/隔离/模型证据及已知边界见[第73轮报告](qq-implementation-2026-11-01-session73.md)。原八阶段其他待签不因新增功能自动通过。
