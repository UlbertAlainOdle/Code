# 每日记忆需求更正

日期2026-11-13，America/New_York。本文件记录用户对第200轮方案的明确纠正。关于每日记忆的对象、生命周期及确认方式，以本文件为准；第200轮探索文档中“七天滑动短期日摘要”和“按群建立日摘要”的建议不再作为实施依据。原文保留为历史，不代表用户同意。

## 两种机制保持独立

已有日记忆/日状态继续保持原样，不修改其计数、读取、遗忘或清理策略。第200轮对该实现的检查只是现状核对，不能据此把用户提出的新功能改为旧状态的扩展或修复。

新增的“每日记忆”是按人与当天私聊对话形成的待保存内容：当天随着达到低价值门槛的对话持续整理、合并和更新，一天结束后再询问是否进入记忆系统。经确认后才把当天整理的内容作为每日条目保存。目标是避免每段有信息的对话都新增一条独立记忆或反复要求确认。

草稿形成、日终待确认、确认入库是不同状态。当天草稿不等于已保存的长期记忆；跨日也不能擅自变成自动入库或七天后到期的短期记忆。未确认草稿的等待期限、日终触发与离线后提示安排尚需在实施设计中明确，本轮不自行设定期限，也不默认半夜向QQ推送。已确认的每日条目如何保留沿记忆系统的明确规则处理，没有新增七天自动删除。

## 两个价值门槛

| 内容 | 对应路径 |
| --- | --- |
| 未达到低门槛 | 沿已有允许的聊天上下文处理，不新增记忆 |
| 达到低门槛 | 持续更新当天这个人的每日记忆草稿，不逐句新增或确认；日终整体询问是否入库 |
| 主人内容达到高门槛 | 可以单独进入重要记忆确认队列，确认后独立保存 |
| 其他人私聊 | 仅保留用户先前提出的低门槛每日路径，不增加高门槛重要记忆系统 |

操作台仍是用户先前提出的确认和操作方向：每日内容完整预览、日终决定与重要内容单独确认可以在该入口承接，减少QQ中的代码类指令和回执。其他人的每日内容由谁确认、可见范围及接收入口需要另行设计，不能擅自投进主人的队列或自动长期保存。

同一内容已独立保存时，日终预览应避免再次保存重复正文；保留时间、条件、否定、作者和来源，不把猜想、问题或助手解释改成用户事实。沿用现有来源有效性、权限、版本、去重和遗忘约束；日终一次确认不代表允许无限正文或无限来源。明确保存或不记请求仍优先于价值评分。

## 对象范围与现有群能力

本次新增每日记忆面向人及其私聊，不新增群每日记忆。个人记忆与个人/群事件保持分开；群事件自理的探索继续按原作者、协调人和来源权限处理，不能据此扩大记忆采集范围。

代码事实补充：现有`qq_group_context.py`还有独立群公共事实和逐条授权个人记忆在群内使用的能力，`GroupPolicy`的context、memory及write开关默认均为false。第200轮实际核对没有群策略条目。本轮仅阅读代码，没有更改或重新查询线上设置。该能力不等于新每日记忆已覆盖群，也不允许将主人私聊记忆自动公开。
