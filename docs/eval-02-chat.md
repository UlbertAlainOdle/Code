# 02｜聊天、模型、流式输出与会话

报告写入 `evaluation_results/02-chat.md`。

## 目标

验证“发消息—完整回答—保存会话—恢复继续聊”这一核心闭环。

## 任务

### 聊天与流式输出

- 测短/长消息、中英文、Markdown、代码块、特殊字符、空消息和超长消息。
- 检查流式片段顺序、重复/遗漏、结束事件、主动停止、刷新、断连和后端异常。
- 检查恶意 HTML 显示，以及错误是否泄露路径、提示词或秘密。

### 模型与模式

- 覆盖可用的 API、本地、Deep 和 Assistant role 路径。
- 模型切换期间重复提交、切换失败恢复、本地模型缺失/加载失败。
- 验证模型、视觉模型、强逻辑模型配置确实生效。
- 检查系统提示、记忆、项目和联网上下文是否进入正确请求且不互相串用。

### 会话生命周期

- 新建、重命名、搜索、加载、继续和删除。
- 刷新后内容和角色顺序一致；快速切换不串消息、不覆盖。
- 两个浏览器标签并用，检查全局 history/模型状态污染。
- 附件、来源、motion 元数据在历史恢复后正确。

### 故障恢复

- mock API 401/429/500、超时、断流、非 JSON；本地推理异常和锁竞争。
- 失败消息可理解、可重试，不产生半条或重复历史。
- 后端重启后已保存会话可恢复；外部失败不能让服务退出。

## 最低验收

至少一种模型完成端到端聊天；流式无明显丢失/重复；会话恢复正确；跨会话零串线；失败可恢复。记录首 token 与完整响应耗时，但本阶段不做压力测试。
