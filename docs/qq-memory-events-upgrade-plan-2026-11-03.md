## 2. 源码现状及原因

### 2.1 时间标签

chat_time_context.timestamp_history只在模型输入投影中插入时间标签；原clock_context已经要求不复制，QQ输出过滤只识别MOTION/MOOD/MC与thinking，未覆盖History标签。因此是输出边界的遗漏，不能通过移除历史时间感知来修。

本轮history_output仅识别行首由应用产生的格式；保留普通日期、正文中解释、行内代码、围栏代码、缩进代码和独立数学块中的示例。网页流式跨任意字符分片也过滤，待判断前缀有界缓存；失败/取消不补发残留。QQ旧待发片段复用原发送边界，不重发已发送消息。原历史文件和用户消息不批量修改。

### 2.2 记忆已有修改能力，但自然补充未完整接通

- 网页显式保存卡可编辑标题/正文/重要性，通过/api/kb/update与expected_version提交。
- 主人好友私聊可/memory search、show、edit；edit依赖memory_management_enabled、shared_memory及memory_write_enabled。第81轮开工修改管理仍关闭，不能据此说更新代码失效，也不代开。
- V4写入管线已有explicit_correct、target_memory_id及同subject/predicate/scope更新，保存证据和revision；目标唯一时能保留ID、更新版本。不是完全没有后端更新。
- 当前自然语言入口缺少稳定的候选定位、补充与替换分类、旧事实保留及确认展示。不能将每条有关旧话题的新句子都自动改写成永久事实。
- evidence含原话/来源引用和观察时间，但不等同于“当时为何产生这条记忆、关联哪件事”的完整来源事件。
- V4到旧网页的投影会将source写为write_pipeline、source_detail重建为管线类型/ID；仅凭这些字段不能可靠识别全部QQ来源。

### 2.3 三种分数不能混称“重要级”

1. importance_score/salience：0～1的重要性权重；V4显式保存/更正未提供时默认0.65，普通候选默认0.35。抽取/action可提供建议，不表示每次均由独立模型认真评了级。被动候选不能自行置顶。
2. 旧网页memory_tier/base_priority_score：about_you为0.90～1.00，curated为0.70～0.89，auto为0.35～0.70；档位主要由来源、管理属性等决定。auto_explicit常落自动档，但V4写入投影为write_pipeline，需看实际记录，不能把所有QQ记忆判为同一档。
3. 当前V4查询排序：相关性0.45、时间0.15、范围0.15、salience0.10、confidence0.10、使用0.05，另有pin加分；它不等于网页的旧分段优先分。

原机制有生效的代码路径，但不是统一、自由跨档的等级制。本轮/memory show明确标“网页兼容评分”，不冒充某次实际召回名次。不能由一条自然召回成功证明所有评分与网页流程全部验收。

### 2.4 当前事件卡

QQEpisodeContext.scope在群公共上下文开启时使用群作用域，否则按原会话/shared/isolated保存；每scope默认3活跃/10总量，尚未按关系调整。当前/events只列当前作用域的有效卡，不是所有人的全局清单。事件与/topic策略都开启才参与；卡片不是长期记忆，会冷却/过期。

## 3. M1：可信来源与记忆产生事件（先完成）

### 3.1 统一来源信封

在主机建立不可由模型/附件伪造的origin结构：channel(web/qq/unknown)、verified_subject、bot/会话/消息引用、observed_at、occurred_at、visibility、origin_version。发生时间未明确时为空，不能用保存时刻冒充事件发生时刻。

- 覆盖QQ显式保存、候选确认、自然确认、edit/未来merge、网页手动/显式/V4写入及重投影。
- origin写入V4 metadata，并按白名单投影到旧source_detail及可见来源标签；保留原有标签，不挤掉已有8项语义标签。通道标签优先使用独立origin字段和UI徽标，必要的来源标签与内容标签分开存储。
- 原始创建来源不因后来从网页修改而变成web；另记last_modified_channel和多来源补充证据。
- 旧记录只有可核验消息/回执关联时才标为verified qq；无法确定标unknown或inferred，不猜测、不获得QQ加权。

### 3.2 来源事件摘要

新增有界context_event：标题、为何保存、原话证据引用、参与主体、发生时间/未知、后续修订引用。摘要建议80～240字软上限，简短事实允许更短，不为凑长复制聊天。

一个事实关联多个来源事件；同一事件也可产生多个独立事实。原事实正文保持简洁可检索，来源事件保留来龙去脉，不把两者混成大段记忆。工作事件卡ID可以关联，但来源不能只依赖会过期的卡片ID；删除临时事件卡不自动删除长期记忆。明确遗忘/撤销来源继续沿用现有依赖失效规则。

来源事件摘要也带可见范围，群中不得因为事实已获授权，就连带公开私人来源故事。未获得完整上下文则只记录当前句子的证据范围，不能宣称已恢复当时完整事件。

### 3.3 验收

隔离库验证各入口投影/重启/来源不可伪造及旧来源unknown；真实QQ只保存一个虚构事实，在网页找到同ID与来源，重启后不变。先验证事实和来源投影，再开发自动合并。

## 4. M2：自然补充、更正与同ID更新

### 4.1 写入流程

直接对话 → 已授权候选检索 → 确定主体/事实键/范围 → 分类create/append/correct/no-op/ambiguous → 展示差异或按明确指令提交 → 原写服务CAS → 读回回执。

- 语义相关不等于同一事实。主体、对象、时间阶段不同分别保存；关于别人的话不能改主人事实。
- append保留仍成立的旧信息，补充新限制或细节；correct将不再成立的旧说法标为被替代并保存修订证据；no-op不新建重复项。
- “这次不保存”、只讨论假设、引用、附件说明、模型自身建议不构成写入许可。
- 目标不唯一时最多列3个可用摘要供选择；没有唯一目标不自行创造“已更新”回执。
- 用户本轮已明确选择：普通补充先预览，明确更新且目标唯一时可直接执行；有歧义再确认。按此实施，不再重复询问。当前只是已确认规则，不表示本轮已经接通自然更新。

### 4.2 版本及一致性

复用KnowledgeBase.update_memory、V4修订、原内容CAS与任务取消；不另建绕过权限的CRUD。预览保存expected_version、主体、范围、旧/新摘要、来源与操作类型，确认只对同一版本有效。网页编辑抢先提交则要求重新预览。

保持memory_id、creation_time和有效权限含义；正文变化后按原规则使旧逐条群授权失效，不能静默继承过时授权。修改历史显示旧→新及来源，修订条数有界，恢复旧版作为新修订提交，不能直接覆盖活动库。操作回执继续有类型且不进入普通人物上下文。

### 4.3 验收

虚构偏好先保存→补充条件→更正原条件→重复补充→网页并发编辑。要求前三次活动记录ID不变、有效信息正确、重复无新条、旧版CAS拒绝；群友/引用文本不能改主人记忆。实机只需主人私聊一条虚构事实两次补充，网页核对一次。

## 5. M3：重要性解释、升降级及QQ来源轻加权

### 5.1 保留分数，分开显示来源档与重要级

迁移前备份并逐项预览。保留现有importance_score/salience和用户手动星标/锁定；不在导入时按内容长度批量重算。来源分类about_you/curated/auto保留为兼容来源档，新增可变化importance_grade，不再用来源档阻止重要性升降。

拟定普通<0.45、关注0.45～<0.70、重要0.70～<0.85、关键≥0.85四级，阈值可版本化配置。上下跨阈值至少0.03的滞回、经一次合法评分更新才变级，避免细小波动抖动。首次迁移按现有数值给初级，之后采用滞回。关键级不等于星标、主人权限或强制每次召回；管理资料及人工锁定规则优先。

### 5.2 分数何时变化

合法补充/更正、主人调整重要性、明确过期或长期适用性改变时评估；不因模型在回答里提到就认定使用、加分。保存score_before/after、规则版本、原因枚举与证据引用，读回可解释。

考虑长期价值、影响、用户强调、事实完整性、独立用户证据和时效。长度只辅助评估信息完整度：简短但完整的姓名、禁忌或偏好不能因为短而降分；长篇重复、来源原文和填充句不能加分。可对新增有效信息量提供最多±0.02的有界调整，先用虚构等义长短对照验证再确定，不把“长”直接当“重要”。

自动更新不能自行pin或解锁；人工明确分数优先且可锁定。临时计划过期可降级，长期身份事实不因几天未提而自动掉级。重要性下降不等于删除，归档/删除继续独立确认。

### 5.3 QQ来源偏好

拟定仅QQ查询时，对已验证QQ来源的salience使用1.08倍率、截顶1.0；不乘整条相关性总分，不把网页来源打折，不写回全局分数，不改变importance_grade。

按当前V4权重，额外加分为0.10×(min(1,salience×1.08)−salience)，至多0.008；以相近相关性时轻微偏向QQ为目标，不能让不相关QQ事实盖过明确命中的网页事实。旧检索回退路径使用同一有界偏好，不形成两套重复加权。所有权限/删除/停用/时效/项目与相关性门槛先执行，再在候选截断前排序。

网页继续使用原规范分数；QQ/memory why显示基础分、来源贡献、生效来源与过滤原因，不能将加权视图显示成永久升档。默认1.08只是拟定值，需对照决定是否调整。

### 5.4 验收

同库同问网页分数/级别不变；QQ同相关性优先级可轻变；强相关网页事实胜过无关QQ事实；unknown及伪造标签无加权；重启不写回增幅。覆盖升级、降级、滞回、手动锁定和等义长短文本。真实模型收益评价与确定性排序合同分开记。

## 6. M4：网页与QQ长期运行机制及管理一致性

用户本轮澄清关注的是长期维持和机制，重点不是重做网页外观。以下长期门槛与M1/M2/M3共同执行；界面只是让状态可核对。

### 6.1 长期积累与事实演化

- 区分长期事实、阶段状态和一次事件。例如偏好保持可更新，某天的行动属于事件，不把“准备做”保存为“已完成”。事实有效起止时间与观测时间分开。
- 新增、补充、更正、重复、冲突各走确定终态；同一事实反复提及不产生新ID或重复事件。无法判断冲突时保留待确认，不让新文本静默覆盖人工确认的内容。
- 不因长期未提自动丢失姓名、持久偏好等；有期限的安排按有效期退出活动召回，归档不等于删除。用户明确忘记或停用继续使派生摘要/索引/待发回答失效。

### 6.2 防止评分和记忆内容自我强化

- 机器人自己的回答、引用旧保存回执、重复摘要、事件卡再次投影不能算新的独立用户证据，也不能累计加重要性或置信度。
- 检索选入不等于实际使用；沿用prompt_included与used的区分。新的QQ倍率仅是本轮排序视图，不回写，更不能每次读取再乘一次。
- 对长度收益、独立证据、使用次数各设上限；保留人工锁定优先、等级滞回与评分原因。定期检查是否只剩常用记忆占满候选、其他明确相关事实再也进不来。

### 6.3 容量、压缩和索引健康

- 优先同事实去重和版本演化，再处理过期事件及低价值重复摘要；不靠无限增加上下文/记忆数量维持召回。
- 摘要必须保留可追溯来源和失效依赖；压缩后核对关键事实、否定、时间、主体、授权及更正关系，不能把过期事实重新压成当前结论。
- V3/V4/词法与向量索引按ID/版本核对。投影或索引失败显示待对账并进行有界修复，不能把失败当不存在而重复保存；不让启动无限重建向量或发生不可见的付费调用。
- 维护任务复用原受管后台，设置预算、频率、取消及停机边界；不另加残留常驻进程或擅自启用Windows自启动。上线前用只读统计确定容量压力，不立即批量压缩生产资料。

### 6.4 长期效果验证

建立虚构、可审阅的多用户长序列：跨天补充与更正、隔很久自然回问、旧事实过期、重复叙述、引用、网页/QQ交替编辑、停用/删除、容量压力及重启恢复。用隔离时钟推进验证30/90天的策略行为，明确标为模拟，不能代签真实04:00跨日或在线时长。

度量自然问法召回命中、旧事实误答、错误主体、未经许可写入、重复活动记录率、V3/V4投影差异、单轮token/延时与维护成本；固定测试集/阈值后再做同条件真实模型对照，保留失败，不以10条唯一关键词的满分替代自然长期效果。生产用正常使用的稀疏样本观察，不要求用户连续守测或导出私人聊天作公共样本。

### 6.5 网页可核对性

优先增加来源筛选、保存落点、ID/版本、来源事件摘要、重要性与评分解释、修改历史和补充预览；来源档、记忆层、重要性、检索得分、星标、锁定必须分开命名。保存回执提供可定位条目，不只弹“保存成功”。

- 网页重要性滑块要验证V3→V4→重启→查询的数值同步；不能只看滑块或数据库某一列。
- 网页和QQ使用同一事实/修订/权限服务，不新建QQ专用事实副本；网页不应用QQ来源倍率。
- 处理V4投影失败/待对账时显示真实状态，不能把“后端写入成功、投影未完成”当全部失败后重存。
- 用户已确认优先长期机制；界面以来源/修订/评分及健康状态可核对为限，不重写无关布局或已确认浏览器设置。

## 7. M5：按用户统一事件与关系容量

### 7.1 身份与可见性分开

个人事件主键以bot_id+已验证subject_qq_id+event_id确定，不以昵称、群号或当前私聊会话作为人的身份。主人在各处仍是同一主人；其他账号各自独立。公共多人事件另存participants，个人事件可关联公共事件，不能把所有群成员合并成一个人。

同一用户在私聊或不同群中的更新应作用于同一事件及revision，容量也是同一个人的总额，不按群复制。**统一事件身份不等于公开私人事件**：每条事件/事实保存来源可见范围。私聊可读取本人有权访问的事实；群中只投影该群公开或明确授权的部分，连私密标题/计数也不得泄漏。群友不能用“这是我的事件”绕过账号或获得主人的事件。

为避免合并后信息过期，latest-state在事件内部统一维护；对当前场合无权显示的新状态，不退而展示已被替代的旧事实。必要时不引用该事件，不能以旧状态制造一致性假象。

### 7.2 查看入口

现有立即可用：/events列当前作用域；/events delete 编号先预览、/events confirm 确认码删除；/events on/off供主人好友私聊，开启前需/topic on。本轮不自动打开。

规划接口：/events self列本人跨场合可见事件；主人私聊/events all分页总览、/events user QQ号查看指定主体；/events show 编号查看当前可见事实/来源/状态；群中只允许本群可见视图，不把全局总览发到群。网页qq-context增加按用户筛选、容量和来源范围，不假装现有/events已经支持这些参数。

### 7.3 容量建议

| 关系 | 活跃/总量（拟定） |
| --- | --- |
| 主人 | 5/20 |
| 重要用户 | 4/16 |
| 熟悉用户 | 3/10 |
| 普通用户 | 2/6 |
| 疏远用户 | 1/3 |

使用主人设置优先的全局关系等级，局部群里的友好分不让同一个人的容量随聊天地点跳变；关系关闭时主人用固定身份额度、其他人保留稳定默认，不能暗开关系学习。关系只决定关注预算，不改变权限、事实可信度或人物设定。

容量减少先冷却低优先事件，不瞬间删除正在讨论的卡；至少保留24小时缓冲供查看/手动保留，之后按统一TTL清理。每人限制之外加全局硬上限与观测预算，阻止大量陌生账号占满内存/存储。初步上限256主体/2000卡，需压力测试后确认；达到上限拒绝新低优先候选，不随机删除主人活跃事件。

保留04:00聊天日降权、暂停/关闭、偏离话题冷却和TTL；事件重要性、人物关系与心情是不同量，心情仅影响表达与回应倾向，不能因一时不耐烦删除事实或改写等级。

### 7.4 迁移

先只读统计旧scope、人数、重名、混合主体和来源可见范围；生成dry-run对应关系。来源主体唯一且可信才迁移；混合群卡拆分或保留为legacy公共事件，不猜主体、不按昵称合并。维护旧ID→新ID映射和revision；原删除确认与待发送快照遇到迁移失效，不能指向另一事件。

使用新的schema/读者兼容标记与迁移账本，幂等并可在副本恢复；不清空生产事件表、旧聊天或原观察台账。无可靠历史时间不补造发生时间。保留功能关闭状态，迁移成功不代表自动启用。

### 7.5 验收

同账号私聊创建虚构计划→群中公开补充→私聊回指；事件ID/版本连续、容量不复制。两个同名账号不串事件；不同群不泄漏未授权来源；群内不显示主人私密标题或全局清单。关系升降容量可解释，下降先冷却，重启/并发更新/删除/停用不复活旧状态。真人只在隔离与迁移门槛通过后安排一个短案例，不要求复杂多端连发。

## 8. 实施次序与完成门槛

T0时间泄漏与只读评分解释 → M1来源/事件证据 → M2自然修订 → M3统一解释与轻加权 → M4网页管理 → M5逐人事件。M4的原有链路只读核对可提前，涉及同一数据模型的改造等M1/M2稳定后实施。

每阶段分别记录：代码/数据兼容检查、隔离测试、真实模型效果、实际QQ/网页验收、部署及原值保留。一次成功不扩大为全问法通过；没有相关改变不重复已签语音/图片/长期召回、不重跑旧付费对照。更新实施状态和新不可变manifest，旧证据与观察缺口不覆盖。

本轮无生产记忆重评分、批量来源回填、事件跨scope迁移、关系容量修改或原开关自动启用；这些均需按本计划逐项实施和验证。
