## 1. 评判与本次证据

现有系统在账号权限、同ID修改、确认后的事务执行、来源归属和遗忘传播方面有可保留的基础，但自然对话的理解、待确认状态与真实写入之间缺少一致合同。当前适合作为受控原型，尚不足以让用户放心依赖日常自动记录。体验问题已经超过单个关键词兼容遗漏；继续增加零散触发词不能形成可靠闭环。

本次两种表达都属于正常交流范围：连续讨论一个世界性问题，以及指向刚才候选或解释的保存请求。系统应承担话题延续识别、指代定位和必要澄清，不能把操作指令的尾部当作记忆事实。

## 2. 根本缺口与整改原则

### 2.1 所有者与陈述对象混在了一起

当前程序只允许subject=self进入个人卡。于是“本人正在研究某个世界性问题”容易被作为general而失去归属；私聊又没有群公共池可接收它。

整改后分开表达：

- **记录所有者**：这是谁的持续讨论，由真实QQ身份和既有个人资格决定。
- **发言者与来源**：谁提出问题、观点、建议或解释，来自哪条真实消息。
- **陈述对象**：讨论的是本人、别人、一般世界问题或共同活动。
- **表达性质**：问题、假设、个人观点、助手推测、已确认限制或共同决定。

有个人资格的人可以拥有关于一般问题的讨论卡。它说明此人正在讨论该主题，不宣称其接受了助手观点，也不把问题写成关于此人的事实。助手给出的概率、比喻或猜测不能自动成为用户信念、客观知识或群共同决定。

### 2.2 尚未建卡的讨论无法积累

当前路由主要获得当前文本、已有卡片及少量群锚点。私聊第一句没有建卡，后面就缺少可靠的接续依据；管理列表还穿插其中，简单截取“最近一条”更不够。

整改后，在原聊天档案上建立有界的对话来源索引和当前主题焦点。给路由提供必要的普通交流，应用命令与回执单独处理。暂不新建另一套长期原话库；原档案、现有证据和事件投影继续使用。

### 2.3 确认器与直接保存入口相互绕开

候选确认器识别固定词；不识别的“记住”会退出确认。另一入口随后把“记住＋任何看似足够长的文字”当作可保存内容。V4意图门和旧显式入口都没有充分拒绝复合指代，单纯切换V4不能解决。

整改后，所有聊天保存入口先得到可核对的目标与正文，再写入。引用候选的回执可以提供主机登记的候选身份，当前用户的话才是授权；回执中的文字本身不能执行指令。

### 2.4 主回答和真实写入使用了不同正文

当前显式捕获在回答后再次处理原输入，可能保存指代尾巴；主回答却自然解释另一段实质内容。真实保存回执可以忠实反映一次错误写入，正常回答仍可能让用户误以为保存了另一段话。

整改后，明确保存由冻结的写入计划负责，成功回执来自真实提交结果。正常回复只描述该结果或预览，不另行承诺保存其他文字。候选提议、解析预览、已提交结果始终分开。

### 2.5 临时话题与长期候选的开关耦合

当前QQ响应器见到非空topic_results时，会在一些情况下关闭本轮memory_write_enabled；结果数组还可能含未提交项。它把“不因临时话题收集而授予长期写入权”与“关闭原来允许的候选建议”混在一起。

整改后分别判断话题采集、被动候选建议和明确长期写入的许可。临时建卡不授予长期保存权；原设置允许的候选建议按自己的规则评估。显式拒绝长期保存必须优先；已有明确写入计划时不再重复提出同一候选。

## 3. 保留、统一及简化的范围

保留现有：身份/好友和重要及以上资格、个人容量、群5活跃/20总量、群仅@、来源32限制及已有整理出口、多人作者与协调人规则、记忆版本/CAS、实际送达确认、操作事务、来源标签及有效视图、遗忘传播、既有降温策略。用户已保存的模型、预算、时区、关系学习、启动/监督及浏览器配置不变。

优先统一三项合同：

1. 每轮使用同一份**对话上下文快照**，区分普通交流、应用回执、待确认问题和有效来源。
2. 每次修改使用明确的**操作目标和写入正文**，所有入口经过同一校验，权限和执行留在主机。
3. 每次结果有明确状态：跳过、无需收录、待定位、待确认、已提交、失败或结果待核对。

不要求把已有服务重写成一个巨大模块，也不要求所有任务塞入一次模型调用。复用现有QQMemoryManagement、QQActionProposals、QQEventOperations、话题路由及存储服务，逐步使它们消费相同合同。先减少重复判断和绕行入口，再评估是否合并内部实现。

## 4. 目标处理流程

```text
已授权入站消息
  → 对话上下文快照（身份、普通交流、主题焦点、实际送达的问题、有效来源）
  → 管理/保存意图与指代定位，或普通话题整理
  → 生成有类型的计划（正文、作者、用途、来源、目标、版本、范围）
  → 主机校验及必要预览/确认
  → 原有服务事务执行，取得真实结果
  → 正常回答使用该结果；保存来源依赖和结果状态
```

普通闲聊没有修改授权时继续正常回答。辅助整理超时、无效或不确定，要保留未整理状态，不能伪称已记录；可选情绪等组件不得因格式差异使主聊天一直失败。已提交的事件与主答失败仍分别报告，不通过重放用户原请求恢复。

### 4.1 对话上下文快照

包含当前原话和真实账号、会话；当前主题及相关普通用户发言、必要助手答复；可用的事件/候选来源；本会话实际送达的待确认问题及其目标/版本。

默认建议使用最近30分钟、最多12个普通交流单元作为未归档路由窗口，按相关性和原预算选择必要材料。这是新增组件的建议上界，不是本轮改写用户窗口设置；实施时需记录配置与原值。命令/回执不计为新的讨论轮，也不占满普通交流窗口。更早的明确命名/引用仍可按可用来源检索；查不到就澄清，不猜造。

一个完整且具体的讨论问题应允许直接建立轻量discussion卡；不够明确的输入可以先保留有期限的焦点/来源索引。它们是原近期聊天的派生索引，不是额外隐藏的个人长期档案，不另设无限容量。有效接续后及时归档，不能连续三轮仍把每句都当作孤立开场。

### 4.2 话题记录的含义

个人卡扩展为“此账号正在接续的主题”，允许subject=general/other，但贡献仍保持实际作者和表达性质。用户提问可成为开放问题，助手回答保留为助手解释或推测；用户明确表达赞同前，不据助手回答生成其个人立场。

优先接续同题；不同对象或新一轮活动才另建。群里仍只使用实际收到的@消息；未观察的群友讨论不可回填。群公共与个人投影继续共用来源身份，个人改写权和协调人定案权保持。

模型自评0.85不能充当正确率证明。主题识别不确定与事实真假不确定分开处理：可以可靠记录“用户提出了某个问题”，无需断言该问题的答案。低置信归属保留待定位原因与可用短期线索，不能静默丢失后还报“全部整理完成”。本方案不把全局降低阈值作为修复。

### 4.3 保存意图与指代解析

识别三类请求：

- 正文自足：“记住：我喝咖啡不加糖。”按原明确保存政策执行，无需机械再问一次同义确认。
- 指向候选：“记住”“保存这条候选”。要求存在同账号、同会话、实际送达且仍有效的唯一可定位候选，绑定候选ID和内容版本。
- 指向对话：“记住你上面说的”“把刚才那段记下来”。从相关来源定位正文，分清用户观点、助手解释和引用内容；有歧义时展示实际候选正文或询问目标。

本次请求同时可能指向系统提出的候选和随后助手解释，不能替用户任意选一个，更不能保存指代短语。建议回应可核对的正文预览；必要时只问“保存你的这条观点，还是我后面的解释？”

解析结果至少含：操作种类、目标ID/来源消息、片段、完整正文、陈述对象、原作者、保存用途、授权人、版本/到期。推断出正文时先预览；用户确认的是该正文和用途。长文摘要须说明是摘要；不能用简短标题假装完整正文已确认。

复合指代未解析时，主机必须阻止显式捕获、V4结构化写入、Agent工具及旧兼容入口落入字面保存。保留未决状态/澄清，不退回正则截取。检查应理解是否依赖上下文，不能简单禁止所有包含“上面”“记忆”的合法句子；明确要求原样记录一个标题或句子仍可通过有类型的字面内容入口。

### 4.4 待确认状态

只读清单、查看详情和解释原因不取消原有效候选。真正换题使通用“好”不再默认确认旧建议，但旧候选可以在原期限内通过明确指向重新选择。拒绝、撤销、内容变更、权限变化、过期或来源失效才按相应规则关闭或重新预览。

确认问题必须实际送达；维护问题的目标、正文版本及前台焦点。内存储存状态与当前对话焦点分开，不依靠“最后一条消息”或全局一个最近ID。搜索建议、记忆候选、事件操作可以有类型地定位；一次普通肯定不能同时执行多种动作。

“记住”只在明确保存上下文中确认记忆；“对的”沿用同一会话/目标/问题绑定。复合条件、否定、改范围须重算预览。已在事件操作中完成的多轮确认原则复用到记忆保存，不重新发明不相容的确认协议。

针对机器人操作回执：合法当前候选回执提供主机登记的对象，引用原文不进入人物聊天，也不成为授权。无关或过期回执、别人的回执、被篡改的转发均不能执行。缺少可验证送达身份时退回预览，不全局放开引用执行。

### 4.5 写入与回执一致

明确保存先准备/确认计划，再由唯一受控执行路径调用原存储服务；旧后置capture_explicit_memory不能重新从原句截取另一份正文。Agent及其他写入口也须使用相同解析结果和主机验证。

候选提议可继续在普通回答后出现，成功保存必须由真实提交结果产生。提交结果绑定memory_id、正文/版本、操作来源、已保存或仅候选状态；正常回复获得相同结果。提交成功而投递失败不重复写，结果未知先查提交结果，不能把普通重试当作新写入。

长期记忆保存用户观点时明确“用户认为”；保存助手解释时保留其作者/讨论性质及用户选择，不能变成确定世界知识。已有用户确认的独立长期记忆继续遵循自己的启用/删除策略，停止临时话题不自动删除它。

### 4.6 来源标签在建卡前就有效

多轮主题可能在后续才形成，早期原话和派生回答不能一直持有空依赖，等建卡后从遗忘保护中漏掉。

在入站时为可用普通消息建立稳定来源身份；主题归档绑定这些已有身份，派生回答继承实际输入来源。来源与卡片关联可以后建立，标签不因后建卡而重新生成身份。更正、停止和删除通过有效视图/屏蔽关系生效，不改写原档案。

现有qq_topic_evidence、消息依赖、来源掩码及归档索引优先复用。若需扩展标签版本或来源类型，按新最低读取能力保护回退，不原地把未知旧标签当作新标签。旧无可靠关联的资料继续执行123轮保守边界，不全量猜测回填。

未归档主题线索、待决整理和依赖它们的确认预览也必须受同一遗忘边界约束。“忘掉所有事件”不能只清正式卡而让线索稍后再生成；单件遗忘屏蔽该主题已关联的来源。没有关联的无关聊天保持。已确认长期记忆与临时话题的使用策略分开，不能把主题停止变成跨系统全删。

遗忘预览应同时说明正式卡与未归档主题线索的作用范围，冻结确切集合及来源版本。不能预览若干张卡，执行时再扩大到所有无关聊天；也不能显示正式卡为零就忽略仍有效的同主题线索。

第141轮补入实际反例。戳一戳的私聊短回复曾直接读取近期聊天缓存，绕开普通回复的事件来源筛选。所有读取近期聊天的入口都应在组装上下文前校验实际来源，并在发送前重验本轮使用的来源。戳一戳还须舍弃失效上下文生成的心情变化。R3入口核对列出普通回复、戳一戳、主动互动、引用和继续发送等各自的读取和重验位置。

### 4.7 可解释状态

每条路由保存内容受限的决策结果：是否调用、跳过原因、各片段的接受/拒绝原因、归属、模型自评分、目标、实际提交结果、来源版本和耗时。日志默认只有代码和计数；原文按现有私有来源权限读取，不复制到公开日志。

None不能同时代表无需记录、低置信、缺上下文、格式错和容量满。普通列表显示真实正式卡；询问“为什么没记录刚才那段”时，可从上一条普通输入的结果说明原因。现有/events why只能解释已有卡，需增加面向最近一次整理的查询能力，具体命令在实施时沿用原帮助风格。

默认聊天保持自然，不每轮输出调试信息。没有写入时不说“已经记下”；长期候选不冒作长期保存；预览不冒作提交。模型自述不能替代可核对状态。

### 4.8 长期记忆的取舍与用途

反复讨论说明主题有接续价值；形成长期记忆还要判断内容是否稳定、以后能否复用、作者和用途是否明确，以及是否取得对应保存授权。

| 内容 | 自动整理的默认去向 | 明确要求长期保存时 |
| --- | --- | --- |
| 一时感受、当次讨论的疑问或猜测 | 临时话题，保留当时语境，不固化为人格或长期偏好 | 保存为有时间/情境的自述、问题或观点，核对实际正文 |
| 持续兴趣、稳定偏好、反复有用的个人背景 | 允许按原设置提议候选，记录支持来源；不因出现次数达到某值就自动确认 | 按原明确保存政策执行，指代不清时先定位 |
| 有截止或结束条件的目标、承诺、安排 | 优先临时事件，记录时间、状态和有效条件 | 明确保存的内容保留其适用范围，结束后不当作仍待执行 |
| 助手解释、概率猜测、一般知识讨论 | 作为讨论内容标明助手来源，不生成用户信念 | 用户选定后按作者和讨论性质保存；不能包装成已证实事实 |

候选评价记录稳定性、复用价值、来源支持、时效、重复与冲突等理由。模型自评和用户关系等级均不能直接代替记忆价值判断。用户明确选择保存的内容不能因自动评分低而悄悄丢弃；内容不完整、权限不足、敏感或来源不明时按相应规则澄清或拒绝，并说明实际结果。

同一内容的重复候选应合并提示或复用已有目标，保留来源，不反复打断聊天。只是重新提问、查看列表或机器人复述，不增加用户支持证据。已保存记忆与候选之间的关系可查，避免同一事实重复占用多个位置。

### 4.9 从正确保存到有依据的召回

复用已有正文检索、来源有效视图、语义检索与排序服务，补齐面向问题的端到端召回合同：

1. 先确定当前问题在问哪个对象、哪个时期，以及要的是当前状态、过去观点、理由还是讨论接续。多个近似目标不能靠最新一条硬选。
2. 只在当前允许使用的来源中召回，联合主题、正文、作者、理由、时间和相关记录，不要求用户复述原句或提供编号。候选记忆不能冒作已经确认的长期事实。
3. 回答“为什么”只使用来源中确有的理由；有立场没有理由时明确材料不足，不推测用户心理。一般主题和助手解释不能变成个人事实。
4. 回答“现在”优先有效版本；明确询问过去时，只读取仍允许查阅的历史并标明当时状态。已遗忘、删除、到期或失权的材料不因历史追问自动恢复。
5. 没召回、当前不可用和从未记录是不同状态。回答依据当前可用记录，不宣称用户从没说过，也不主动带出无关旧安排。

独立已确认长期记忆按自己的启用/删除策略读取，临时事件停止不会扩大为跨系统全删；引用依据必须与当前实际使用的来源一致。来源、版本、有效时间与置信/不确定状态保留在主机侧，主回答只取得当前必要材料。

召回验收以问题所需信息集合为单位：例如询问某次选择的原因，应找到该选择和已记录理由，排除另一个项目、另一人的立场及被更正版本。检查检索材料与最终回答两个层面，不能仅凭“工具命中了一条记录”签收。

### 4.10 长话题与长期记忆维护

维护目标是减少日常重复与无效材料造成的手工负担，保持原容量和有效来源约束。复用现有摘要、候选去重、记忆分层/归档、群拆分和生命周期服务，补齐它们对真实长对话的联合行为。

- 当前状态摘要包含有效观点、条件、分工/进展、未决问题及关键分歧；每项能回到原来源。新内容、更正、撤回、停止和到期使相应摘要更新或失效。
- 去掉确实重复的表达、整理索引、清理自然到期缓存可以自动完成，不能因此改变原作者、含义、权限或期限。不同作者同文、条件相近和观点改变不能按普通重复吞并。
- 摘要节省上下文空间，不自动减少实际证据数量。达到来源32或原卡容量时，仍须遵守真实限制；不能把多条有效来源改成一条无证据摘要来绕过上限。
- 自动整理无法在保留有效信息的前提下完成时，正常聊天继续，明确哪些新内容未归档，并提供可审阅的整理/分支方案。涉及多作者、语义合并或删改的原权限和预览保持，不为了免人工就静默丢掉异议。
- 长期记忆更新保留原创建来源及版本链。稳定偏好、当时观点、阶段目标和已结束安排按各自时效读取，不因一段时间未提及就物理删除已确认事实，也不因反复被机器人引用而永久续期。

热度、重要度、可使用状态和存储生命周期各自记录。查看列表、询问现状、重复投递或助手自动提醒不充当新的用户贡献，不制造活跃度和长期支持证据。保持已确认的淡出规则，新增维护行为不能补回旧过期来源。

#### 4.10.1 标签、时间与语义共同参与归并（第137轮方案补充，尚未实施）

用户建议对事件和长期记忆都使用“短期内标签重合”进行合并。采用其候选筛选思路：共用候选检索和关系判定合同，事件与长期记忆分别执行自己的归属、确认、生命周期和维护政策。临时事件与独立长期记忆可以关联，不能通过整理自动跨越长期保存授权。

处理顺序为：**有效来源和权限筛选 → 标签/主题/正文相似度及时间接近筛选候选 → 核对同一对象、事实属性或活动轮次 → 判断关系 → 主机验证并执行 → 更新派生摘要和来源关联。** 标签和时间只决定优先检查哪些记录，不单独授权合并。表面同标签不证明同一事件，标签不同的同义表达也不能直接排除。

- 时间分别记录消息发生、事件实际发生/截止、最近有效接续和原来源到期。今天一起讨论的本周与下周两次活动仍是不同轮次；长期偏好隔月重复仍可检索为同一事实。短期窗口是优先级，不是唯一检索范围或新的保留期限，不在本轮拍定统一阈值或权重。
- 先核对个人所有者、群归属和操作权限，再比较内容。不同人的个人事实不混成同一事实；群公共话题可以整合多人的贡献，但每条作者、条件和异议保留，共同定案仍遵守协调人规则。共用公开原话可继续双投影，不能把整张私人卡作为群合并正文。
- 语义判定区分对象、属性、时间、条件、否定、表达性质和活动轮次。用户观点、助手解释、转述、假设、问题及已确认安排分别处理；模型仅提出基于实际来源ID的关系计划，不能凭标签生成“共同结论”或替他人改写。

| 内容关系 | 允许的默认处理 | 必须保留的边界 |
| --- | --- | --- |
| 同作者/对象/属性/条件下的同义重复 | 复用既有事实或主题，减少重复展示，追加新的有效来源关联 | 同一消息的重投递、助手复述不增加支持次数；来源ID去重，不按正文删除独立证据 |
| 同一事件/主题的信息互补 | 同卡追加或生成联合视图；长期记忆可保留多属性条目并关联 | 不能把“喜欢咖啡”和“晚上不喝咖啡”压成丢失条件的一句话；相关不等于重复 |
| 同一属性出现变化、矛盾或多方分歧 | 明确本人更正才按原版本合同更新；否则保留并列观点/冲突待定 | 不把较新的时间戳或较高自评分当作真相，不用合并消除另一人的限制 |
| 只有宽泛标签相关，或属于新一轮活动 | 建立主题关联/检索分组，保持独立记录 | 不因同日、同名、同地点就折叠两个项目/两次活动；不确定时保持分开并记录原因 |

事件重点核对同一活动轮次和有效接续；长期记忆重点核对同一事实属性及其适用条件。先改善归属与同卡追加，减少新碎片产生，再处理已有多卡/多记忆归并。不能用事后批量合并掩盖路由不断建错卡。

#### 4.10.2 归并的来源、结果与可撤销性

合并视图和摘要必须保存成员记录、实际来源ID、版本及依赖关系；原作者、创建来源、有效时间、确认状态、锁定/重要保护和既有原始证据可追溯。纯索引/展示整理和原已授权的同题追加可自动完成；改变已确认正文、覆盖或归档记录时沿用原授权、版本/预览和保护合同，不因标签相同另开绕行入口。本轮不启用旧的定时自动合并或运行历史批处理。

合并计划绑定确切目标集合和版本，提交前重查权限、来源及保护状态；集合变化则重新核对。重试以操作身份查已有结果，未知结果不自动重放。继续复用原存储事务/逐项结果，不承诺跨库全局原子性。保留原ID与归并映射，使旧引用可定位当前有效对象；撤销归并应可重建原关系，不要求用户重发聊天。

来源被停止、更正、删除、自然到期或成员失权时，联合视图/摘要必须重算或失效；新窗口、候选检索、合并和撤销均不能恢复被禁止使用的来源。其他仍有效的来源可继续提供独立支持，但不能显示已经失效的细节。独立长期记忆的启用/删除仍按自己的授权处理。

摘要不等于释放来源配额：先以稳定来源ID核对去重，再计算实际保留证据并遵守原32来源和卡片容量；不同作者同文不是一个来源。达到上限且无法无损处理时，保留旧有效材料、说明新内容未归档，沿用整理/拆分出口，不能只把多条证据包装成一条摘要绕过限制。

#### 4.10.3 归并实施顺序与验收

阶段顺序保持：R2继续解决归属/接续和预建卡来源；R3先完成统一操作/来源失效/真实结果合同，并为归并预留操作类型；R4建立召回基线；R5实施候选检索、重复证据整理、联合摘要及受保护归并，并复核受影响的召回；R6验证完整使用。可以提前在隔离样例上设计和检查，前置门禁未过不扩开运行范围，不替代当前未完工作。

### 4.11 旧入口收敛的硬门槛

R0建立聊天写入口清单，至少列出QQ候选确认、显式保存、后置捕获、V4结构化写入、Agent工具及共用网页聊天写入，记录调用路径和实际校验位置。共用存储的手动表单/导入保持自身明确授权合同，不能被聊天指代规则误当成待解析命令。

R1—R3允许分步接入；R3完成必须满足：

- 聊天写操作都有可追踪的计划/操作身份，绑定同一份正文、对象、来源、权限和版本；真正执行继续复用原事务服务。
- 旧入口只做参数兼容和转发，不再独立截取一份正文、自行解释模糊肯定或另设成功判断。新解析返回待定位/拒绝时，旧正则和工具入口不能继续落库。
- 一次已提交操作的断网重试先按操作身份查结果，不重新生成另一份正文。结果未知时明确待核对，不冒称失败后又重复写。
- 操作状态和成功回执由主机提交结果生成；正常回答引用同一结果。对未保存、仅候选或预览的内容，不用自由生成的成功承诺代替真实状态。

用入口清单逐项证明上述条件；“主要入口已接入、旧分支以后再看”不能作为收敛完成。原历史来源、CAS和确认权限继续保留，不通过移除保护来减少分支。

### 4.12 最终效果与可靠性边界

交付目标为自然交流下可用、结果可核对、失败可恢复。自然语言可能存在多个合理解释；此时应把不确定性留在待定位、预览或澄清阶段。不能承诺所有未来输入都零误判，也不能用这一点接受错写、假回执或无提示的数据丢失。

| 日常使用 | 最终验收要求 |
| --- | --- |
| 同题提问、追问、表达观点，中途查清单 | 能维护同一讨论，分清问题、立场与助手解释 |
| 指向上文保存，随后查看完整记忆 | 正文指向正确，必要时先澄清；详情、回执和正常回答一致 |
| 隔天换种问法询问原因或接着讨论 | 在当前有效来源中找回主题及已记录理由，不强迫记原话/编号 |
| 更正观点或安排，再询问现在/过去 | 当前与历史明确，原作者和适用时间不漂移 |
| 忘掉话题，再正常聊别的内容 | 同主题的正式卡、未归档线索、摘要、待发及派生上下文受约束，无关有效内容保留 |
| 讨论变长或达到容量 | 常见重复能整理，关键条件与分歧保持；确实未归档时有真实结果和整理出口 |
| 来源不足、模型判断失败或投递中断 | 澄清或报告当前真实状态，操作可查可恢复，无重复写入和持续失败循环 |

用户不应经常手工纠正保存目标、上网页核对正文或重新建卡才能继续。仍反复依赖这些补救时，模块只能标为阶段性试用，不能签作完成。

## 6. 必须覆盖的常见验收场景

| 场景 | 预期 |
| --- | --- |
| 同一一般主题的提问→追问→本人观点，中间查看清单 | 同一讨论卡，问题与观点分开；清单命令不切断主题 |
| 只问一次无接续价值的工具性短问题 | 可不建卡，有正常理由，不为了增加卡数强存 |
| 多轮交错两本书、两个方案 | 按对象接续；代词不靠全局最新卡硬接 |
| 发出候选提议→查看事件或记忆→“记住” | 仍可定位该候选，版本有效才执行，不保存“记住”文字 |
| 候选和助手解释同时在上文→“记住上面那条” | 展开正文预览或澄清，不替用户任意选择 |
| 新话题后回答“好” | 不确认旧保存或搜索建议；明确指向旧候选可重新核对 |
| 两个候选、“都保存”、随后排除一项 | 主机枚举和预览确切集合，不静默增删或部分成功冒称全部 |
| 用户问题、用户担忧和助手概率猜测 | 作者、对象、表达性质独立，助手估计不变成用户事实 |
| 讨论“记忆/记住”的概念 | 正常聊天，不被词语本身触发写入 |
| 明确要求原样记一个含指代词的标题 | 有完整字面目标时允许，不靠禁词误杀 |
| 引用候选回执或他人的转发回执 | 只接受已送达/同人同会话有效对象的当前授权，不能执行引用文字 |
| 候选已变更、超时、来源停止/删除或成员失权 | 重新预览或拒绝，不从私有备份恢复旧正文 |
| 第一轮未建卡、第二轮归档、随后忘掉主题 | 早期原话、助手派生和未决线索同样停止自动回流 |
| 停止或删除后戳一戳，再追问“那个实验” | 戳一戳使用仍有效的片段，生成期间来源失效则丢弃该决定。后续追问只有在有效上下文能定位唯一目标时才接续，否则先澄清，避免从同类实验中猜一个 |
| 用户遗忘后主动提出相似新话题 | 可作为新来源重新讨论，旧ID、已废弃条件不自动恢复 |
| 群多作者分歧、合格好友双归属 | 作者和权限不变，未@来源不回填，协调人规则只作用于共同决定 |
| 话题收集失败、情绪读取异常或主答失败 | 不误报已保存；辅助失败不形成持续主答阻断；已提交结果仍可查 |
| 写入后断网、重复投递、并发修改 | 绑定提交结果/幂等键，重试不重复记，版本变化重看正文 |
| 容量或来源32满额 | 保留有效来源并给出未提交原因，不能静默丢分歧或自动扩大容量 |
| 短期情绪、稳定偏好、阶段目标和一般讨论分别反复出现 | 按用途和时效处理，重复次数不直接变成长期保存授权 |
| 已明确选择保存一条当时的观点 | 内容完整且授权有效时尊重选择，保留情境；不因自动价值分低就丢掉 |
| 保存选择及原因，隔天用同义问法询问 | 检索与回答找齐对应理由，不混入另一件事或推测动机 |
| 同一偏好/安排有旧版、新版、已停止来源 | 现在/过去按权限和有效版本分别回答，不因相似度高回流废弃内容 |
| 话题延长、多次摘要、更正或撤回后再提问 | 摘要与原来源一致，关键条件、不同作者和异议未丢失 |
| 从旧显式捕获或Agent工具传入未解析保存指令 | 同样停在定位/预览，不能绕过统一写入校验 |
| 更换为后续本地模型 | 同一身份/正文/来源/确认合同及关键反例仍通过，不靠模型名放宽写权限 |

工程测试须走实际入口、实际时间适配器和真实来源；模拟模型用于故障注入。语义验收需另用真实配置的模型处理自然表达，不能只喂事先构造的正确计划。使用私有原样重放及跨主题虚构对照，覆盖至少两种不同表达，不为每个修复让用户重做整套旧实验。

质量评价以目标正文正确、主题连续、归属正确、澄清有必要及失败可恢复为核心。记录误收/漏收、误归属、指代解析、澄清次数、保存与回执一致、被遗忘来源回流、阶段调用与延迟。卡片数量和测试数量不能代表体验改善；模型自评分不能代替这些指标。

R4—R6需额外记录按问题标注的必需信息/禁止引用集合、检索漏项与误项、回答是否有依据、时间/版本选择和维护前后丢失情况；按实际尝试次数记录，不只展示成功样例。加入未用于提示调试的自然表达与多主题连续会话，防止围绕本次原句硬编码。

验收材料至少覆盖日常生活、一般兴趣和持续项目；组合换题、只读清单、澄清、过期、更正、隔天追问和遗忘。模拟故障使用可控时钟/临时数据，不伪造长期线上观察。源变更只运行有依赖的回归；真实模型样例、真人QQ和既有证据分开，模型切换也沿用这套合同。
