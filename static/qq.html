群列表

待审核邀请

主人身份直接按已配置 QQ 号验证，与共享记忆开关独立。主人在 QQ 私聊发送 /whoami 可确认身份，/groups 查看群，/requests 查看邀请。

开启主人邀请自动处理后，主人邀请机器人入群会自动同意并开启该群 @回复；其他人的邀请需审核。也可开启“主人首次 @授权新群”，兼容 QQ 直接入群的情况。手动关闭的群不会被自动重新开启。关闭回复不退群，群聊不读取个人记忆。

首次配置

  1. 安装并启动 NapCat，登录用于自动回复的 QQ 账号。
  2. 启用 HTTP 服务端：127.0.0.1:3000，配置独立的访问 Token。
  3. 启用 HTTP 客户端，上报地址设为 http://127.0.0.1:8000/api/qq/events，消息格式选择 array，上报 Token 对应 SAYA_QQ_WEBHOOK_SECRET（HMAC 签名密钥），关闭自身消息上报。
  4. 按项目 docs/qq-bridge.md 配置启动环境中的 SAYA_QQ_* 变量。至少需要账号、双向 Token 和白名单，然后重启 Saya；使用单个应用进程。
  5. 先检查连接，再由白名单好友发送文字；白名单群内请 @机器人。

记忆与能力边界

默认只保留每位 QQ 发言人在当前会话中的近期上下文。不同好友、不同群、同群不同发言人分别隔离，不读取或写入个人长期记忆、日记或项目上下文。

仅显式配置的主人好友私聊，可在开启 SAYA_QQ_SHARED_MEMORY 后共用 Saya 长期记忆。网页与 QQ 的聊天历史独立；角色设定和模型资源共用，角色设定中请勿存放私密资料。

当前支持文字对话、长回复分段、身份查询、群邀请审核、群回复启停，以及 /help、/status、/memory、/reset。图片、语音、文件、自动加好友和 QQ 内游戏控制暂不支持。

消息发送结果不明确时不会自动重发，避免重复回复。详细功能、故障排查和数据保留规则见项目接入文档。
